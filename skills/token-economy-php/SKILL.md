## Правила (строго)

1. Один раз за разговор, прежде чем читать или править файлы, вызови `info`: он назовёт режим проекта (Битрикс / Laravel / MODX / «CMS не определена — универсальный»), кодировки и состав файлов.

**CodeGraph рядом.** `info` сохраняет поля `integrations.codegraph` (`available`, `cli_version`, `index`, `db_path`, `reason`) и добавляет полный абсолютный `executable`, `source` (`path` или `home`), `hint` (строка или `null`). CLI ищется сначала в `PATH`; только при отсутствии кандидата — в домашнем `.local/bin` (`os.homedir()` в JavaScript, `os.path.expanduser('~')` в Python). Имена: `codegraph.cmd`, `codegraph.bat`, `codegraph.exe` на Windows; `codegraph` на POSIX. Неработающий кандидат в `PATH` не маскируется; выбранные `executable`/`source` сохраняются при ошибке проверки версии. Детект запускает лишь `version` с таймаутом 2 с: без `index`/`init`, чтения содержимого базы и кэша детекта. Нет CLI — `reason=not_installed`; нет индекса — `reason=no_index`: прежний путь, не структурный `explore`.

`hint` заполняется только после успешной домашней проверки. Если он не `null`, обязательно покажи его на языке разговора, при необходимости переведи. Подсказка объясняет необязательное ручное добавление домашнего `.local/bin` в `PATH` и полный перезапуск приложения для новых терминалов. Не меняй автоматически `PATH` процесса/пользователя, профили оболочки или реестр. Домашний CLI работает сразу только при `available=true` и `index=true`, даже если команда `codegraph` без пути отсутствует в `PATH`.

Если в проекте есть `.codegraph/` и CLI CodeGraph доступен (`op=info` показывает `available=true` и `index=true` в `integrations.codegraph`), структурный вопрос — сначала `"<absolute-path-from-integrations.codegraph.executable>" explore "<question>"`: обязательно подставь возвращённый абсолютный `executable`, а не вызывай `codegraph` без пути. Примеры структурных вопросов: как работает X, кто вызывает Y, что заденет правка Z, обзор незнакомой подсистемы — один вызов вместо серии `search` и чтений. Свои операции остаются на то, чего у CodeGraph нет: `sig` (сигнатуры из node_modules/.d.ts), замена тела метода/функции (`edit_symbol`), генерация сущностей (Angular CLI), `outline`, точный поиск текста (`search`: конфиги, стили, шаблоны), точные диапазоны (`graph op=read`) и паспорт проекта (`op=info`). Точные строки для правки или цитирования — не из вывода explore: он для понимания, координаты берутся `graph op=read` или штатным чтением файла. Пусто или ошибка — уйти в прежний путь один раз: не повторять вызов с другой формулировкой и не объяснять пользователю, что «граф не нашёл». `codegraph index`/`init` без явной просьбы не запускать: это перестройка индекса на минуты и запись в проект. Нет `integrations.codegraph.available` в ответе `info` — правило не действует, работаем как раньше.

2. Режим определяет доступные профильные операции: Битрикс — правила и операции Битрикса в `references/bitrix.md` (прочитай перед их использованием); Laravel — в `references/laravel.md`; MODX — в `references/modx.md` (сниппеты/чанки/шаблоны в БД файловому индексу недоступны — об этом предупреждает `info`); «CMS не определена» — универсальный режим: профильные операции не вызывай, работай общими (`search`, `outline`, `symbol`, `deps`, `rdeps`, `path`, `node`, `stats`, `metrics`, `read`, `patch`, `patch_symbol`, `create`).
3. Если `info` показал файлы в cp1251 или UTF-16LE/BE, читай их только операцией `read`, правь только `patch`, создавай только `create`: штатная запись UTF-8 меняет кодировку. UTF-16 определяется по BOM; без BOM кодировка не угадывается.
4. Файл меньше 300 строк читай напрямую (в cp1251 — через `read`). Файл от 300 строк — сначала `outline`, затем точечное чтение диапазона (`read` с `offset` и `limit` либо Read(offset, limit)).
5. Где определён класс, метод, функция, константа или ORM-таблица — `symbol` (метод ищется и по цепочке наследования, в базовых классах). Где встречается текст — `search`.
6. Перед правкой общего файла (помощник, класс, подключаемый во многих местах) вызови `rdeps`: он покажет, кто использует файл (классы, require/include, вызовы, обработчики).
7. Правки штатным инструментом разрешены только в файлах UTF-8 (по `info`). Файл длиннее 50 строк при правке менее 30% целиком не перезаписывай: используй `patch` или штатную точечную замену.
8. Индекс строится и обновляется сам при каждом вызове — это анализ, не запуск проекта; запускать можно всегда. Папку `.bx-cache` не читай.
9. Не запускай `php -l`, `composer`, `artisan`, тесты и сборку — проверки выполняет пользователь.
10. Скрипт работает только с путями внутри рабочей директории; пути вне проекта отклоняй.

### Обзор и чтение

info — паспорт проекта: режим (Битрикс / Laravel / MODX / универсальный), кодировки, стиль кода, число файлов, крупнейшие файлы. В Битриксе — корень сайта, версия, `utf_mode`, шаблоны сайта, свои модули и компоненты. В Laravel — версия из `composer.json`, структура каркаса (8–10 или 11+), пространство имён, число маршрутов, моделей, миграций и локалей. В MODX — редакция, файловые элементы и предупреждение об элементах в БД.

search — поиск подстроки или регулярки с учётом кодировки (кириллица находится и в cp1251). Результат — текст, сгруппированный по файлам: по умолчанию до 30 совпавших строк (`limit`), сниппеты до 120 символов содержимого вокруг первого совпадения плюс маркеры `…` (до двух); префикс номера строки в этот лимит не входит. Итог показывает полные количества совпавших строк и файлов, при усечении — `показано N`; no-match — `«query»: совпадений нет (просмотрено файлов: N)`, exit0. Ошибки — `Ошибка: ...`, exit1. NUL-содержащие файлы пропускаются.

outline — оглавление файла: классы с диапазонами строк, методы с сигнатурами, функции, константы, enum-кейсы. С `"inherit":true` добавляет методы предков. Список объявлений ограничен 60 строками; при усечении печатается точный count (`показано 60 из 142 объявлений`) с подсказкой `limit=0 — вывести все`, а `limit=` задаёт свой предел (0 — вывести всё); extras-блоки (компоненты, маршруты, модели и т.п.) и inherit-блоки в предел не входят. Принимает путь, часть пути или имя класса. В Битриксе дополнительно показывает ORM-таблицы, вызванные компоненты, ключи `$arResult`/`$arParams`, обработчики событий; в Laravel — директивы Blade, связи модели, миграции; подробности в references.

read — чтение файла с номерами строк с учётом кодировки: `offset=1`, `limit=200` по умолчанию (0 включает default, не вывод всего файла). Несколько диапазонов за один вызов: `ranges=10-20,30-40` или JSON-массив чисел/пар (границы 1-based, включительно); `ranges` несовместим с `offset`/`limit`. Перекрывающиеся и вплотную соседние диапазоны сливаются, между блоками с зазором печатается разделитель пропуска. Конец диапазона обрезается по EOF, начало за EOF — ошибка; суммарно больше 2000 фактически читаемых строк в режиме `ranges` — отказ без усечки. В режиме `offset`/`limit` этого капа нет.

### Навигация

symbol — где определено: класс, интерфейс, трейт, enum (по полному или короткому имени), `Класс::метод`, функция, константа. Вывод: `имя  вид  файл:строка_начала-строка_конца`; до 20 результатов, затем `… ещё N`. `all=true` снимает фильтр вариантов СУБД, но не кап вывода.

deps / rdeps / path / node / stats / metrics — граф связей. `deps`/`rdeps`: `depth=1` по умолчанию, диапазон 1–5; до 60 связей, затем `… ещё N`. `node` печатает список объявлений файла (классы, затем функции) с итогами: по умолчанию страница 50 строк, `limit` задаёт размер страницы (0 — весь список), `offset=0` — смещение от начала списка; связи ограничены 40 в каждую сторону независимо от `limit`. Типы связей в выводе:

| Тип | Что значит | Где работает |
|---|---|---|
| class | `new`, `X::`, `extends`, `implements`, `use` (трейты и импорты) | во всех режимах |
| function | вызов функции, объявленной в проекте | во всех режимах |
| include | `require` / `include` со статически вычисляемым путём (`__DIR__`, `$_SERVER["DOCUMENT_ROOT"]`, …) | во всех режимах |
| component / template | `IncludeComponent("ns:name", …)` → файл компонента и шаблона | Битрикс |
| event handler / module / lang | обработчики событий, подключение модулей, языковые файлы | Битрикс |
| template / lang (Blade) | `view('name')`, `@extends`, `__('group.key')` → шаблоны и локали | Laravel |
| snippet / chunk / include | теги `[[!snippet]]`/`[[$chunk]]`, `runSnippet`/`getChunk`, Fenom `file:` → файловые элементы | MODX |

hotspots — «где болит» по git-истории во всех режимах, только чтение истории, индекс PHP не строится (`.bx-cache` не трогается). По каждому файлу, менявшемуся за период: `коммитов`, `churn` (сумма добавленных и удалённых строк; бинарники — коммит считается, churn нет), `авторов`, `багфиксов` (subject по `/\b(fix|fixes|bug|hotfix|hotfixes|исправ|баг)\b/i`; `\b` в JS — ASCII-граница, кириллические ветки на практике не срабатывают) и `churn/стр` (только файлы от 50 текущих строк; размер — текущее число строк файла, чтение с потолком 5 МБ). Процентили `p50/p90/p97` считаются внутри репозитория: метка `pNN` — «значение достигло NN-процентильной границы по этой метке»; в таблице top у файла печатается старшая из его меток, в `file=` — метка каждой метрики. Аргументы: `top` (по умолчанию 15), `file=ПУТЬ` (один файл: персональные метки и дата последнего касания), `since` (`<N>d` или `YYYY-MM-DD`, по умолчанию 180d), `max_commits` (потолок прохода, по умолчанию 2000, упор отмечается «история могла быть обрезана»). Сбор — один проход `git log --no-merges --no-renames`: переименования не отслеживаются (rename приходит как удаление + добавление), merge-коммиты не считаются. В режиме Битрикса `bitrix/modules/**` и `upload/**` не считаются относительно найденного корня сайта: для `www` это `www/bitrix/modules/**` и `www/upload/**`, аналогично для остальных поддерживаемых docroot. Пользовательский код `local/modules/**` остаётся в статистике. Префиксные исключения входят в ключ валидности кэша. shallow-клон помечается «история неполная»; пустая история — «коммитов за период нет» (exit 0); каталог без git — «Ошибка: не git-репозиторий» (exit 1). Кэш — `.git-signals.json` в корне проекта; HEAD читается файлами `.git`, поэтому валидный кэш отдаётся даже без git в PATH.

### Метрики файлового графа

`metrics` работает во всех четырёх режимах и принимает `file=<путь>` **либо** `top=<N>`; вместе запрещены. `top` — положительное safe integer (≤ 9007199254740991), default 15; без обоих аргументов — top-15. `depth` — строго целое 1..5, default 2 **только для metrics**; default `deps`/`rdeps` остаётся 1.

- `fan_in` / `fan_out` — уникальные проектные файлы по входящим/исходящим рёбрам; разные типы одной пары считаются одной связью.
- `dependents(depth)` — уникально достижимые обратным BFS файлы не дальше `depth`; `impact` — все обратнодостижимые файлы **без ограничения глубины**. Корень исключён из обоих счётчиков.
- `pagerank` — 20 итераций с damping 0.85 и равномерным распределением dangling mass. `percentile` — midrank `(less + halfEqual) / N * 100`, округлённый в тексте до `pN`; вычисляется на всём графе.
- Top: `fan_in` desc, затем `pagerank` desc, затем стабильный путь asc.

Все существующие типы рёбер входят (`class`, `function`, `include`, `component`, `template`, `event handler`, `module`, `lang`, MODX `snippet/chunk`), внешние endpoints не добавляются. `core=true` сохраняет прежнюю семантику: включает ядро Битрикса/MODX, но не отменяет vendor/cache и остальные служебные фильтры. Пользовательские модули, включая `local/modules/acme.module`, остаются в индексе без `core=true`. Это статический **файловый** граф, не символьный или полный runtime call graph и не гарантия риска правки; учитываются только уже найденные индексом связи.

Вывод — общий текст: `src/helpers.php  fan-in 12 (p95)  fan-out 4  dependents(2) 27  impact 41  pagerank 0.0132 (p95)`. Неизвестный файл — `Ошибка`, exit1, подсказка `op=stats` (и прежняя core-подсказка, если применима); пустой граф — `Граф пуст: <root>/.bx-cache/index.json`; цикл — `циклов: N` без подсказки `op=cycles` (такой операции нет). На прогретом индексе metrics не меняет граф и parse-кэш; холодный вызов законно строит их.

### Изменение

patch — точная замена фрагмента с сохранением кодировки (UTF-8 / cp1251 / UTF-16LE/BE с BOM), BOM и перевода строк (CRLF / LF). Ровно одно вхождение (`"all":true` — все). Символ, который нельзя записать в cp1251, отменяет запись целиком; некорректные входные байты UTF-16 и непарные суррогаты в новом публикуемом UTF-16 отклоняются до записи. Проверка нового представления общая для `patch`, `create` и `patch_symbol` (включая dry), при отказе исходные байты остаются нетронутыми; это не PHP lint.

patch_symbol — правка тела метода или функции без чтения старого тела в контекст: заменяется только содержимое между `{` и `}`, а сигнатура, модификаторы, doc-комментарии, кодировка (UTF-8 / cp1251 / UTF-16LE/BE с BOM), BOM и переводы строк (CRLF / LF) остаются байт в байт. Параметры: `file` и `symbol` (`Класс::метод` или `имя_функции`) — обязательные; тело — ровно одно из `body` (последовательности `\n`, `\r`, `\t` в строке раскрываются) или `body_file` (файл внутри проекта); `dry` по умолчанию `true` (компактный отчёт без записи); `indent` = `auto` (по умолчанию — базовый отступ старого тела, относительные отступы строк тела сохраняются; для пустого тела — отступ строки с `{` плюс шаг 4 пробела), `2`/`4`/`tab` — отступ объявления плюс шаг, `raw` — как передано. Отказ без правки (файл остаётся нетронутым): символ не найден или метод abstract/интерфейсный (унаследованные тела не правятся), класс или функция найдены в нескольких файлах, в одном файле несколько одноимённых объявлений, файл бинарный, новое тело несбалансировано по скобкам, `body_file` вне проекта, символ непредставим в cp1251.

`file` в `patch_symbol` — точный путь относительно `root`, как в результате `symbol`: абсолютный путь или иной alias того же файла не совпадёт с путём узла индекса. `body_file` читается как UTF-8 и не удаляется. Баланс скобок не заменяет проверку PHP-синтаксиса.

create — новый файл; для текста с не-ASCII символами кодировка по умолчанию — UTF-8 либо cp1251 по преобладанию в проекте (при равенстве UTF-8); ASCII-текст создаётся как UTF-8. `enc=utf8|cp1251|utf16le|utf16be` задаёт явно (принимаются и `utf-16le`/`utf-16be`); UTF-16 создаётся с BOM; `eol=crlf` переводит строки в CRLF, иначе LF. Публикация не перезаписывает файл, появившийся параллельно. Пути проверяются через realpath, включая ссылки и отсутствующие родительские каталоги.

build — принудительная перестройка связей индекса; разбор файлов с прежними mtime/size переиспользуется из кэша, заново читаются только изменённые.

## Выполнение команд (PowerShell)

Команда — одна строка, параметры передаются argv-аргументами `ключ=значение` (разделитель значения — первый `=`), обязательный параметр каждой операции — `op`:

    node "<SCRIPTS_DIR>\bx.js" op=info

Не используй пайп (`|`), `;`, `&`, `$()`, backtick, `>` и переносы строк — права среды их отклоняют, прежние вызовы через stdin-пайп больше не проходят. Права разрешают вызов по имени скрипта, поэтому полный путь в двойных кавычках допустим: команда выглядит как `node "<SCRIPTS_DIR>\bx.js" ключ=значение…`.

`<SCRIPTS_DIR>` — папка `scripts` этого скилла: возьми полный путь этого SKILL.md и замени имя файла на `scripts`. Каталог скиллов агента: ZCode — `%USERPROFILE%\.zcode\skills\…` (в репозитории проекта — `.zcode\skills\…`), Kilo Code — `%USERPROFILE%\.kilocode\skills\…` (в репозитории — `.kilo\skills\…`, Linux/macOS — `~/.config/kilo/skills/…`).

Значения аргументов: с пробелами — в одинарных кавычках; апостроф внутри значения удваивается (`''`); значения, начинающиеся с `$`, тоже бери в одинарные кавычки, иначе PowerShell раскроет их как переменные; двойные кавычки `"` внутри значений не используй — PowerShell 5.1 их портит. Кириллица через argv не портится: node читает командную строку через Unicode API Windows. Для многострочных payload (`patch`/`create`) — файл параметров: запиши JSON штатным инструментом в `.bx-cache/payload.json` (папка вне git) и передай его через `@.bx-cache/payload.json`.

`@payload` — UTF-8 JSON внутри `root`: argv разбирается до чтения всех файлов; последний явный `root=` задаёт границу, без него используется cwd. Относительный путь payload разрешается от этой границы. Проверяются lexical/realpath containment и обычный файл существующим безопасным resolver; внешние пути, внешние symlink/junction, dangling links и каталоги отклоняются. Допустимые внутренние ссылки и root-junction сохраняются. Поле `root` из файлового JSON игнорируется и не может разрешить ни сам файл, ни выход операции за выбранную границу. Несколько `@` сливаются слева направо; явные argv (последнее значение ключа) приоритетнее JSON независимо от позиции. JSON из stdin по-прежнему поддерживается, если после argv/payload не задан `op`; без файлового payload его `root` допустим, явные argv приоритетнее.

Общие параметры: `root` (рабочая папка, по умолчанию текущая), `core` (`true` — включить ядро Битрикса или MODX в индекс и поиск; служебные исключения vendor/cache остаются).

info:

    node "<SCRIPTS_DIR>\bx.js" op=info

search (`ext=.php` по умолчанию; `regex`, `ignoreCase`/`i`, `path`, `limit=30` — по желанию; `limit=0` возвращает default 30):

    node "<SCRIPTS_DIR>\bx.js" op=search query=getUserInfo path=src

symbol:

    node "<SCRIPTS_DIR>\bx.js" op=symbol name=App\Services\Billing
    node "<SCRIPTS_DIR>\bx.js" op=symbol name=Billing::recalc

rdeps / deps (`file` — путь, часть пути или имя класса; `depth` 1–5):

    node "<SCRIPTS_DIR>\bx.js" op=rdeps file=src/Support/helpers.php depth=2
    node "<SCRIPTS_DIR>\bx.js" op=deps file=index.php

metrics (одна цель либо рейтинг, `core` сохраняет прежние фильтры):

    node "<SCRIPTS_DIR>\bx.js" op=metrics file=src/Support/helpers.php depth=2
    node "<SCRIPTS_DIR>\bx.js" op=metrics top=15
    node "<SCRIPTS_DIR>\bx.js" op=metrics file=local/modules/acme.module/include.php

path / node / stats:

    node "<SCRIPTS_DIR>\bx.js" op=path from=index.php to=App\Core\Launcher
    node "<SCRIPTS_DIR>\bx.js" op=node file=src/Services/Billing.php offset=50

hotspots (git-сигналы «где болит»):

    node "<SCRIPTS_DIR>\bx.js" op=hotspots top=10
    node "<SCRIPTS_DIR>\bx.js" op=hotspots file=src/Services/Billing.php
    node "<SCRIPTS_DIR>\bx.js" op=hotspots file=www/local/modules/acme.module/include.php

outline:

    node "<SCRIPTS_DIR>\bx.js" op=outline file=src/Services/Billing.php

read:

    node "<SCRIPTS_DIR>\bx.js" op=read file=src/bootstrap.php offset=1 limit=120
    node "<SCRIPTS_DIR>\bx.js" op=read file=src/bootstrap.php ranges=10-20,30-40

build (принудительная перестройка индекса):

    node "<SCRIPTS_DIR>\bx.js" op=build

patch и create (для многострочных значений используй `@`-файл параметров; однострочные `old`/`new`/`text` принимаются и через argv; перевод строки внутри JSON-строк — `\n`):

    node "<SCRIPTS_DIR>\bx.js" @.bx-cache/payload.json

Содержимое `.bx-cache/payload.json` для правки:

    {"op":"patch","file":"src/config.php","old":"define('SITE_TITLE', 'Сайт');","new":"define('SITE_TITLE', 'Мой сайт');"}

Для правки тела метода одним непрерывным фрагментом (старое тело читать не нужно; вызов без `"dry":false` покажет отчёт без записи):

    {"op":"patch_symbol","file":"src/X.php","symbol":"Класс::метод","body":"...","dry":false}

Для нового файла:

    {"op":"create","file":"src/Support/helpers2.php","text":"<?php\nfunction hello() {}\n"}

Примеры и правила для режимов фреймворков — в references: `references/bitrix.md` (Битрикс: правила, профильные операции, устройство индекса и ограничения), `references/laravel.md` (Laravel), `references/modx.md` (MODX). Режим текущего проекта называет `info`.
