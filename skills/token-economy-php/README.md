# token-economy-php

Скилл для агента Kilo Code: экономит токены при работе с PHP-проектами и сайтами на 1С-Битрикс, включая старое API (до D7) и D7. Вместо чтения каталогов и десятков файлов агент вызывает скрипт `bx.js` и получает короткий ответ: где определён класс, кто подключает файл, какие страницы вызывают компонент, кто обрабатывает событие, где задано сообщение, какой файл обслуживает URL.

Правила для агента и примеры команд PowerShell — в `SKILL.md`. Устройство индекса и подробные ограничения — в `references/bitrix.md`.

## Требования

- **Node.js 18 или новее.** Код использует только возможности Node 12+, проверен на Node 22. Пакеты из npm не нужны, сеть не нужна.
- **PHP не нужен.** Разбор выполняет собственный лексер в `scripts/lib/php.js`, проект не запускается.
- **Проект:** обычный PHP или 1С-Битрикс любой версии (старое API и D7 в одном индексе). Корень сайта определяется сам: папка с `bitrix/` или `local/`, в том числе вложенная `www`, `public_html`, `httpdocs`, `web`, `public`, `htdocs`, `site`, `docroot`.
- **Git** не обязателен. С ним список файлов берётся из `git ls-files` (учитывается `.gitignore`), без него — обход каталогов.
- **Ядро Битрикса** (`bitrix/modules/main`, `iblock`…) в рабочей папке нужно только для операций с `"core":true`. Если ядра в репозитории нет, остальное работает без него.
- **Запуск** из корня проекта или с параметром `root`.
- **PowerShell:** в Windows PowerShell 5.1 перед командой с кириллицей добавляй `$OutputEncoding=[Text.Encoding]::UTF8;`. Для правок с кириллицей надёжнее файл параметров (`"@.bx-cache/payload.json"`).
- **Права:** скрипт пишет только в папку `.bx-cache` в корне проекта (кэш, внутри лежит `.gitignore` со звёздочкой) и, при `patch` и `create`, в указанный файл.

## Установка

Скопируй папку `token-economy-php` в каталог навыков Kilo Code:

    глобально на Windows:   %USERPROFILE%\.kilocode\skills\token-economy-php
    локально в репозитории: .kilo\skills\token-economy-php
    Linux и macOS:          ~/.config/kilo/skills/token-economy-php

Структура:

    token-economy-php/
      SKILL.md                правила и команды для агента
      README.md               этот файл
      references/bitrix.md    устройство индекса, ограничения, старое API
      scripts/
        bx.js                 точка входа, все операции
        lib/                  лексер PHP, индекс, классификация файлов Битрикса, кодировки

Проверка: `'{"op":"info"}' | node scripts\bx.js` в корне сайта выводит корень сайта, версию Битрикса, `utf_mode`, кодировки файлов, шаблоны, свои модули и компоненты.

## Что умеет

| Задача | Операция |
|---|---|
| Профиль проекта: корень сайта, версия, `utf_mode`, кодировки, шаблоны, модули, компоненты, стиль кода (D7 или старое API) | `info` |
| Где определён класс, метод (в том числе унаследованный от `CAll*`), функция, константа, таблица ORM | `symbol` |
| Оглавление: классы с диапазонами строк, сигнатуры, поля ORM-таблиц; для страниц и шаблонов — вызванные компоненты, модули, ключи `$arResult` и `$arParams` | `outline` |
| Кто использует файл, что использует он, цепочка связей | `rdeps`, `deps`, `path`, `node`, `stats` |
| Компонент: файлы, параметры из `.parameters.php`, шаблоны и переопределения по сайтам, все вызовы | `component` |
| Обработчики событий (`AddEventHandler`, `registerEventHandler`, `RegisterModuleDependences`) и вызовы `GetModuleEvents` | `events` |
| Языковое сообщение по ключу или по тексту, где оно используется | `lang` |
| Какой файл обслуживает URL: физический файл или правило `urlrewrite.php` | `route` |
| Схема таблицы: D7-класс и поля, `CREATE TABLE` из `install/db/mysql/install.sql`, где встречается | `table` |
| Поиск по тексту с учётом кодировки | `search` |
| Чтение, правка и создание файлов с сохранением cp1251 / UTF-8, BOM и CRLF | `read`, `patch`, `create` |

Связи в графе: класс, функция, `require`/`include`, `IncludeComponent` (на файл компонента и на шаблон), `IncludeFile` и `main.include`, класс или функция-обработчик события, `IncludeModule` (на `include.php` модуля), языковой файл. Старое API: глобальные классы, методы в базовых `CAll*`-классах, варианты `classes/mysql`, `mssql`, `oracle`, константы `BX_ROOT`, `SITE_DIR`, `SITE_TEMPLATE_PATH`, синтаксис PHP 5.

Скорость (синтетический проект на 3300 файлов): первая сборка индекса около 1,2 с, повторный запрос около 0,3 с. Пример экономии: сводка `component` занимает около 350 байт вместо примерно 1800 байт трёх файлов компонента.

## Чего скрипт не видит

- **Данные из базы:** свойства и типы инфоблоков, почтовые шаблоны, агенты, настройки модулей (`b_option`), обработчики, зарегистрированные в БД и не вписанные в код.
- **Маршруты и разделы:** D7-маршруты (`local/routes`), правила `.htaccess`, `.section.php`, меню (`$aMenuLinks`).
- **Динамические имена:** компонент или класс, заданный переменной; пути вида `"classes/".$DBType."/…"`; вызовы `$obj->method()`.
- **Типы в сигнатурах** параметров как самостоятельная связь (связь даёт их `use`-импорт).
- **`registerAutoLoadClasses` и `AddAutoloadClasses`** не разбираются: классы находятся по самим объявлениям в файлах.
- **SQL в коде:** запросы `$DB->Query("… FROM b_table")` связей в граф не дают, `table` лишь показывает файлы, где имя таблицы встречается текстом.
- **JS, CSS и не-PHP файлы** шаблонов (для них используй `search` с `ext`).

## Что учесть

- **Первый вызов за разговор — `info`.** Он покажет кодировку файлов и предупредит, если есть cp1251.
- **cp1251.** Если в проекте есть файлы в windows-1251, штатные инструменты агента портят кириллицу. Для таких файлов используй `read`, `patch` и `create`: они сохраняют кодировку, BOM и перевод строк, а символ, которого нет в cp1251, отменяет запись целиком.
- **Ядро по умолчанию не индексируется.** Модули без точки в имени (`main`, `iblock`, `sale`…), компоненты `bitrix:*` и `bitrix/admin` считаются ядром. Соответственно модуль без точки в имени, написанный в проекте, тоже будет считаться ядром и попадёт в индекс только с `"core":true`.
- **Исключаются:** `vendor/` в местах composer (`vendor`, `local/vendor`, `bitrix/vendor`), `upload`, `bitrix/cache`, `managed_cache`, `backup`, `updates` и подобные служебные каталоги, файлы больше 2 МБ. Имя `vendor` в пространстве имён компонентов (`local/components/vendor/…`) не исключается.
- **Варианты под разные СУБД.** Классы из `classes/mssql` и `classes/oracle` скрыты, если есть основной вариант; `"all":true` в `symbol` показывает все.
- **`route`** переводит условия `urlrewrite.php` из PCRE в JavaScript. Простые выражения совпадают, сложные (именованные группы `(?P<…>)`, рекурсия, флаг `u`) могут отличаться.
- **Кэш.** Папка `.bx-cache` исключает себя из git сама. Если ответы выглядят устаревшими после обновления скилла, удали эту папку.
- **Проверка.** Скилл проверялся на синтетических проектах (D7, старое API, cp1251) на Linux с Node 22, реальный PHP при этом не запускался. На Windows, в PowerShell и на боевом сайте перед использованием стоит выполнить `info`, `component` и `events` и сверить результат с кодом.
