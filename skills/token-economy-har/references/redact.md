# Очистка HAR

Перед `redact`, передачей HAR/вывода другим людям или агентам, либо оценкой сохранности/анонимности очищенного файла прочитай этот файл.

`redact` удаляет чувствительные заголовки и cookies, очищает чувствительные расширения заголовков/параметров и `timings`, маскирует токены в URL/query/параметрах и поддерживаемых структурированных телах. Поддерживаются JSON и form-urlencoded, в том числе в base64 при корректном UTF-8. HTML, plain text, CSS, JavaScript, непрозрачные, бинарные и неразбираемые тела удаляются целиком вместе с `encoding`. Размеры и числовые тайминги остаются исходными, даже если очищенное тело меньше. Не передавай оригинал вместе с очищенной копией.

Параметры OAuth `code/state`, API `key`, подписи `sig/hmac` и токены во фрагментах URL, включая `#/route?code=...`, тоже маскируются. Значения URL/form декодируются для очистки и при изменении кодируются обратно; нетронутые пары и повторы сохраняются. Приватные PEM-блоки очищаются в поддерживаемых строках; незавершённый блок не оставляет материал ключа. Чрезмерно глубокие данные заменяются с общим пределом глубины 24, включая вложенные записи и ссылки. Обычные не-URL строки общего обхода метаданных/расширений длиннее 512 единиц UTF-16 после очистки заменяются целиком; это не лимит URL, значений заголовков/параметров или строк JSON-тел.

JWT очищаются целиком, включая `alg=none` в формах `header.payload.` и `header.payload`; пятисегментные JWE — включая пустой encrypted key. В свободном тексте (`title`, `comment`, строки JSON) чувствительные пары `token=...`, `access_token=...`, `password=...` очищаются до границы значения; поддерживаются кавычки и percent-encoded имена. Нейтральные `code/state/key` без URL/form-контекста не считаются секретами. Токены и URL userinfo не обрезаются на 4 KiB: распознанное значение удаляется целиком, длинные несекретные строки JSON сохраняются.

Все строковые `pages[].id` преобразуются в уникальные для разных исходных id значения `page-N`; соответствующие `pageref` используют ту же таблицу даже в потоковом режиме, когда метаданные поступают после записей. Исходно корректные связи сохраняются, секретные исходные id в копию не возвращаются. Сетевые сведения, включая `serverIPAddress`, `connection` и обычные IP в расширениях, сохраняются и не анонимизируются.

Произвольные секреты под нейтральными именами, вложенные JSON/base64-строки и персональные данные могут остаться; очистка не является гарантией анонимности. `--compact` и предел вывода не являются очисткой.

Файл назначения должен быть **новым**: исходный HAR и существующий `clean.har` не перезаписываются. При битом входном HAR незавершённая копия удаляется; готовый файл публикуется только после полного разбора, атомарно через hard link. Файловая система **каталога назначения** должна поддерживать hard links (FAT/exFAT и часть сетевых ФС не подходят), нужны права на запись. Замены на `rename`/копирование нет: при ошибке публикация безопасно отклоняется. Диагностика записи/публикации содержит операцию и исходный код I/O; ошибка доступа сама по себе не доказывает отсутствие поддержки hard links. Это не гарантия сохранности при аварийном отключении питания.

`redact` пустого HAR успешно публикует очищенный файл (`redacted:true`, `requests:0`), но возвращает exit1 как признак отсутствия записей, а не ошибки записи.
