# token-economy-har

[English version](README.md)

Экономный разбор HAR на Node.js без npm-зависимостей. Применяйте для сводки сетевых запросов, медленных ответов, ошибок, самых тяжёлых ресурсов и дублей, сравнения двух захватов и очистки секретов — без открытия многомегабайтного `.har` в контексте и без ручного разбора его JSON.

## Требования

- **Node.js 18 или новее.**
- **Без npm-зависимостей:** каталог работает копированием целиком, `npm install` не нужен. `har.js` лежит рядом с этим README.
- **Вход:** файл `.har` (`--file path` или `--file=path`); без `-f`/`--file` либо с `-f -` HAR читается из stdin. Индексы записей начинаются с **0** и одинаковы во всех командах.

## Установка

Скопируй папку `token-economy-har` в каталог навыков агента. Точка входа — `har.js` рядом с `SKILL.md`:

```powershell
node "<SKILL_DIR>\har.js" info -f "capture.har"
node "<SKILL_DIR>\har.js" slow -f "capture.har" --top 10 --min 500 --json
node "<SKILL_DIR>\har.js" entry 42 -f "capture.har" --body 2k --json
```

Порядок для нового захвата: `info`, затем `slow` или `errors`, затем `content` и `dup`.

## Что умеет

| Команда | Результат |
|---|---|
| `info` | Число запросов и страниц; размеры тел; p50/p95/p99/max; статусы, методы, домены, MIME |
| `slow --top 10 --min 500` | Самые медленные запросы; `blocked/dns/connect/ssl/send/wait/receive` в мс. Без `--min` порог 0 |
| `errors` | HTTP >= 400, отсутствие ответа, статус 0, `_error`, таймауты и явно пустые ответы |
| `domains --sort size` | Размеры и суммарное время по доменам. Сортировка `size` (по известному несжатому объёму, по умолчанию), `count`, `time`; `--top N` |
| `content` | Категории контента, переданный и несжатый размер; `--by-mime` группирует по MIME |
| `dup --strategy exact` | Одинаковые URL; `norm` убирает шум и хеш имени файла; `hash` сравнивает записанные тела ответов |
| `search <regex> --limit 30` | Регулярное выражение JavaScript по URL, методу и статусу, с учётом регистра и без флагов. Не ищет в телах |
| `entry N` | Заголовки запроса/ответа, метаданные и фазы. `--body 2k` дополнительно показывает ограниченные тела |
| `waterfall --top 20` | Первые по времени начала запросы, их смещения и длительности в общем интервале записи |
| `diff a.har b.har` | Появившиеся/исчезнувшие URL, рост среднего времени/размера и изменение числа запросов |
| `redact -o clean.har` | Валидный HAR без стандартных секретов; исходные размерные показатели сохраняются |

Все команды поддерживают `--json`; `--pretty` форматирует JSON только вместе с `--json`. `--compact` — opt-in вместе с `--json`; перед использованием или декодированием прочитай `references/compact-output.md`.

## Ограничения вывода

- Жёсткий предел 200 строк и 8 KiB действует на любую команду, включая справку; большой `--limit` его не снимает. `--limit N` ограничивает число элементов данных (по умолчанию 30; `info` — 5 доменов и MIME, `slow/domains` 10, `waterfall` 20; вместе с `--top` действует меньшее значение).
- Тела отсутствуют в выводе всех команд по умолчанию. `entry N --body 2k` показывает ограниченное тело (суффиксы `k/m` — 1024/1048576 байтов, границы UTF-8 сохраняются); проверяй `truncated`.
- Списки JSON несут `total`, `shown`, `omitted`, `items`, `truncated`; JSON никогда не обрывается посередине элемента. `truncated: true` может означать обрезку поля даже при `omitted: 0`.
- Любой `truncated:true` (включая обрезку поля/тела) запрещает считать выдачу полной.
- Для файлов **больше 200 MiB** `--stream` включается автоматически; stdin всегда потоковый.

## Примечания

- Не открывай многомегабайтный HAR инструментом чтения файлов и не разбирай его JSON вручную: даже одна строка `response.content.text` может занимать мегабайты.
- `search` и `entry` не маскируют секреты: URL/query, заголовки и явно запрошенные тела могут содержать токены и cookies. Ограничение вывода и `--compact` — не очистка; для передачи вывода сначала создай очищенный HAR и анализируй его.
- Перед передачей HAR или вывода другим людям/агентам, перед `redact` либо оценкой анонимности прочитай `references/redact.md`: автоматическая очистка не гарантирует удаления всех персональных данных.
- Коды завершения: **0** — есть данные, **1** — подходящих записей/изменений нет, **2** — неверные аргументы, ошибка чтения/записи или битый HAR. Диагностика идёт в stderr; с `--json` диагностическое сообщение тоже JSON.
- Для тестов/benchmark прочитай `references/testing.md` и получи разрешение пользователя; используй только собственный синтетический HAR без cookies/tokens.
