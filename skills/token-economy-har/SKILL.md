# Skill: token-economy-har

## Когда И Как

- Есть `.har`, нужно понять, что загружалось, что тормозит, что весит, где ошибки и дубли.
- Порядок: `info`, затем `slow` или `errors`, затем `content` и `dup`.
- Не открывай HAR через Read/read_file и не разбирай его JSON вручную. Даже одна строка `response.content.text` может занимать мегабайты.
- Тела отсутствуют в выводе всех команд по умолчанию. Для одной записи используй `entry N --body 2k` и проверяй `truncated`.
- Перед передачей HAR другим людям или агентам выполни `redact`. Автоматическая очистка не гарантирует удаления всех персональных данных.

## MegaMemory и сравнение

При доступной MegaMemory применяй общий порядок из `rules/RULES.md`, раздел «megamemory», проверяя root/version и опоры; без неё продолжай обычный разбор. Память не доказывает актуальное содержимое записи. Для тестов/benchmark используй только собственный искусственный HAR без cookies/tokens; живые и чужие HAR требуют отдельного разрешения. Cwd — анализируемый проект, `har.js` передаётся абсолютным путём отдельно от входного `--file`. Общего TS/PY/HAR dispatcher нет; `lang` MegaMemory его не включает.

No-match — не ошибка: `search` возвращает JSON `items:[]`, `total:0`, exit1. Проверяй payload и stderr; error exit2, malformed/пустой stdout не принимается как корректный negative. Любой `truncated:true` (включая обрезку поля/тела) запрещает считать выдачу полной; исходные неизвестные размеры/времена квалифицируются отдельно от truncation.

## Запуск

Node.js >= 18. Каталог работает копированием целиком, `npm install` не нужен. `<SKILL_DIR>` означает каталог этого `SKILL.md`; вход CLI находится рядом: `har.js`.

Команда всегда одной строкой, аргументы через argv, без перенаправлений, пайпов и shell-разделителей. Флаги можно ставить до или после подкоманды. Поддерживаются `--file path` и `--file=path`; пути с пробелами заключай в кавычки.

```powershell
node "<SKILL_DIR>\har.js" info -f "capture.har"
node "<SKILL_DIR>\har.js" slow -f "capture.har" --top 10 --min 500 --json
node "<SKILL_DIR>\har.js" entry 42 -f "capture.har" --body 2k --json
```

Без `-f/--file`, либо с `-f -`, HAR читается из stdin. В PowerShell используй путь к файлу, не собирай пайп вручную. Индексы записей начинаются с **0** и одинаковы во всех командах.

## Команды

| Команда | Результат |
|---|---|
| `info` | Число запросов и страниц; размеры тел; p50/p95/p99/max; статусы, методы, домены, MIME |
| `slow --top 10 --min 500` | Самые медленные запросы; `blocked/dns/connect/ssl/send/wait/receive` в мс. Без `--min` порог 0 |
| `errors` | HTTP >= 400, отсутствие ответа, статус 0, `_error`, таймауты и явно пустые ответы |
| `domains --sort size` | Размеры и суммарное время по доменам. Сортировка `size`, `count`, `time`; `--top N` |
| `content` | Категории контента, переданный и несжатый размер; `--by-mime` группирует по MIME |
| `dup --strategy exact` | Одинаковые URL; `norm` убирает шум и хеш имени файла; `hash` сравнивает записанные тела ответов |
| `search <regex> --limit 30` | Регулярное выражение JavaScript по URL, методу и статусу, с учётом регистра и без флагов. Не ищет в телах |
| `entry N` | Заголовки запроса/ответа, метаданные и фазы. `--body 2k` дополнительно показывает ограниченные тела |
| `waterfall --top 20` | Первые по времени начала запросы, их смещения и длительности в общем интервале записи |
| `diff a.har b.har` | Появившиеся/исчезнувшие URL, рост среднего времени/размера и изменение числа запросов |
| `redact -o clean.har` | Валидный HAR без стандартных секретов; исходные размерные показатели сохраняются |

```powershell
node "<SKILL_DIR>\har.js" errors -f "capture.har" --json
node "<SKILL_DIR>\har.js" content -f "capture.har" --by-mime --limit 10
node "<SKILL_DIR>\har.js" dup -f "capture.har" --strategy norm --json
node "<SKILL_DIR>\har.js" search '[45][0-9]{2}' -f "capture.har" --limit 10 --json
node "<SKILL_DIR>\har.js" diff "before.har" "after.har" --json
node "<SKILL_DIR>\har.js" redact -f "capture.har" -o "clean.har" --stream
```

## Ограничения Вывода

- Все команды поддерживают `--json`; `--pretty` форматирует JSON отступами. По умолчанию компактный русский текст.
- `help --json` и `help --json --pretty` сохраняют полный текущий текст справки и переводы строк; общий предел вывода действует и для справки.
- `--limit N` ограничивает число строк данных; стандартно 30, для `info` 5 групп, `slow/domains` 10, `waterfall` 20. Вместе с `--top` действует меньшее значение.
- Жёсткий предел: 200 строк и 8 KiB, включая завершающий перевод строки. Большой `--limit` не отключает этот предел.
- Списки JSON содержат `total`, `shown`, `omitted`, `items`, `truncated`. При бюджетной обрезке счётчики обновляются, JSON никогда не обрывается посередине.
- URL и заголовки тоже ограничены. `truncated: true` может означать обрезку поля, даже если `omitted: 0`.
- `--body` без размера означает `2k`, в том числе в форме `--body entry N`. Суффиксы `k/m` означают 1024/1048576 байтов; границы UTF-8 сохраняются. Для бинарного base64-тела возвращается ограниченный base64, для текстового декодированный UTF-8.
- Тело содержит `bytes`, `shownBytes`, `encoding`, `text`, `truncated`. Общий предел вывода может дополнительно уменьшить запрошенный объём.

## Точность Анализа

- `bytes.uncompressed`: `content.size >= 0`, иначе известный `response.bodySize`. Оценки по `bodySize` считаются в `estimatedUncompressed`.
- В `info.bytes` поле `transferred_known` содержит сумму только известных `response.bodySize >= 0`; `transferred_unknown_count` считает записи с неизвестным `bodySize`. При таком счётчике больше нуля `transferred_is_lower_bound: true`, а текст сообщает «не менее ...; неизвестно для ... записей». Отдельного поля с якобы полным переданным объёмом нет.
- `info.bytes.compression` суммирует `content.size - bodySize` только при известных обоих исходных размерах. `unknownCompression` считает неизвестные пары; при их наличии текст обозначает известную часть через «не менее» и «разницы размеров», не объявляя её полной экономией.
- В размерах одной записи (`entry.sizes.transfer`) и группах известный `bodySize` по-прежнему дополняется оценкой `content.size - compression`, если она возможна. Это правило не используется в общей сумме `info.bytes.transferred_known`.
- Отсутствующие/отрицательные размеры не подменяются измеренными нулями: используются `transferred_unknown_count`, `unknownUncompressed`, `unknownCompression`, а в группах также `unknownTransfer`. Суммы относятся только к известным значениям; оценка несжатого объёма по `bodySize` не меняется.
- Размеры относятся к **телам ответов**, не к HAR-файлу, заголовкам или всей сетевой передаче. Наличие `content.text` не меняет записанные размеры.
- SSL в HAR входит в `connect`. В разбивке `slow/entry` из `connect` вычитается SSL, чтобы не считать его дважды; неизвестные фазы возвращаются как `null`.
- Процентили вычисляются методом ближайшего ранга. Сумма длительностей и интервал записи различаются из-за параллельных запросов.
- `info.time.span` и `waterfall.span` показывают известный интервал. При неизвестном старте или длительности это нижняя оценка: `time.spanIncomplete` у `info` и `spanIncomplete` у `waterfall` равны `true`, в тексте есть пометка. Без известных стартов интервал равен `null`; неизвестные старты/длительности остаются `null`/`?`, а не измеренными нулями.
- `errors` не считает нормальные пустые HEAD, 1xx, 204/205 и 3xx ошибками. Отсутствующее в HAR тело при положительном записанном размере не означает пустой ответ.
- `norm` убирает `_`, `timestamp`, `cacheBust` и похожие cache-параметры, сортирует query и заменяет хеш имени (`app.4f2a1b.js` на `app.*.js`). Это эвристика, не доказательство одинакового ресурса.
- `hash` учитывает декодированные байты base64; записи без захваченного тела не участвуют. Одинаковые URL не означают, что повторный запрос избыточен.
- `diff` сопоставляет метод и нормализованный URL. Время/вес сравниваются как средние по запросу, отдельно от количества; при неизвестных значениях сравнение соответствующей метрики пропускается.
- `search` передаёт аргумент в `new RegExp(pattern)` без флагов. Синтаксис `/pattern/flags` не поддерживается: слеши и суффикс будут частью шаблона.

## Память И Безопасность

`--stream` разбирает `log.entries` по одной записи с учётом JSON-строк и экранирования, проверяя весь документ, включая конец. Для файлов **> 200 MiB** включается автоматически; stdin всегда потоковый. В потоковом режиме не удерживаются все тела, но память агрегатов не всегда постоянна. Очень большая отдельная запись или метаданные всё ещё требуют соответствующей памяти.

- `info` хранит O(N) известных длительностей для точных процентилей и группы по числу уникальных значений.
- `domains` и `content --by-mime` хранят только выбранные группы, без массива длительностей; память растёт с числом разных доменов/MIME. `content` без `--by-mime` использует фиксированный набор категорий.
- `dup` и `diff` удерживают группы уникальных ключей; `redact` хранит соответствия различных id/pageref страниц. Потоковый режим не устраняет эти накопления.

Неоднозначные повторы корневого `log` или его поля `entries` отклоняются в обоих режимах.

`redact` удаляет чувствительные заголовки и cookies, очищает чувствительные расширения заголовков/параметров и `timings`, маскирует токены в URL/query/параметрах и поддерживаемых структурированных телах. Поддерживаются JSON и form-urlencoded, в том числе в base64 при корректном UTF-8. HTML, plain text, CSS, JavaScript, непрозрачные, бинарные и неразбираемые тела удаляются целиком вместе с `encoding`. Размеры и числовые тайминги остаются исходными, даже если очищенное тело меньше. Не передавай оригинал вместе с очищенной копией.

Параметры OAuth `code/state`, API `key`, подписи `sig/hmac` и токены во фрагментах URL, включая `#/route?code=...`, тоже маскируются. Значения URL/form декодируются для очистки и при изменении кодируются обратно; нетронутые пары и повторы сохраняются. Приватные PEM-блоки очищаются в поддерживаемых строках; незавершённый блок не оставляет материал ключа. Чрезмерно глубокие данные заменяются с общим пределом глубины 24, включая вложенные записи и ссылки. Обычные не-URL строки общего обхода метаданных/расширений длиннее 512 единиц UTF-16 после очистки заменяются целиком; это не лимит URL, значений заголовков/параметров или строк JSON-тел.

Все строковые `pages[].id` преобразуются в уникальные для разных исходных id значения `page-N`; соответствующие `pageref` используют ту же таблицу даже в потоковом режиме, когда метаданные поступают после записей. Исходно корректные связи сохраняются, секретные исходные id в копию не возвращаются. Сетевые сведения, включая `serverIPAddress`, `connection` и обычные IP в расширениях, сохраняются и не анонимизируются.

Произвольные секреты под нейтральными именами, вложенные JSON/base64-строки и персональные данные могут остаться; очистка не является гарантией анонимности.

Файл назначения должен быть **новым**: исходный HAR и существующий `clean.har` не перезаписываются. При битом входном HAR незавершённая копия удаляется; готовый файл публикуется только после полного разбора, атомарно через hard link. Файловая система **каталога назначения** должна поддерживать hard links (FAT/exFAT и часть сетевых ФС не подходят), нужны и права на запись. Замены на `rename`/копирование нет: при ошибке публикация безопасно отклоняется. Диагностика записи/публикации содержит операцию и исходный код I/O; ошибка доступа сама по себе не доказывает отсутствие поддержки hard links. Это не гарантия сохранности при аварийном отключении питания.

Коды завершения: **0** есть данные, **1** подходящих записей/изменений нет, **2** неверные аргументы, ошибка чтения/записи или битый HAR. Диагностика идёт в stderr, без traceback и без фрагментов тел; с `--json` диагностическое сообщение тоже JSON.

`redact` пустого HAR успешно публикует очищенный файл (`redacted: true`, `requests: 0`), но возвращает код **1** как признак отсутствия записей, а не ошибки записи.

## Приёмка

Тесты, фикстуры и бенчмарк находятся в репозитории разработки, в каталоге `tests/token-economy-har/`; в скопированный скилл они не входят. `<REPO_DIR>` означает корень репозитория agent-skills. Не запускай тесты, линтер или сборку без разрешения пользователя.

Команда тестов после разрешения:

```powershell
node --test "<REPO_DIR>\tests\token-economy-har\har.test.js" "<REPO_DIR>\tests\token-economy-har\parse.test.js" "<REPO_DIR>\tests\token-economy-har\redact.test.js"
```

Воспроизводимый бенчмарк без npm создаёт временные искусственные HAR, измеряет CLI в отдельных процессах, сравнивает первые 100 записей и удаляет свои файлы. `--real` задаёт реальный HAR для замеров `info/slow`; без него используется искусственный файл 34 MiB. `--temp` задаёт проверенный каталог временных файлов; искусственный файл по умолчанию 300 MiB (`--size N`).

```powershell
node "<REPO_DIR>\tests\token-economy-har\benchmark.js" --temp "<TEMP_DIR>" --real "sier40.evolenta3.ru.har"
```
