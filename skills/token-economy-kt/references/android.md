# token-economy-kt: детали индекса, ролей и ограничений

## Что индексируется

| Тип файлов | Как используется |
|---|---|
| `*.kt` | полный разбор деклараций: классы, интерфейсы, объекты, enum, companion, typealias, функции (в т.ч. suspend, operator, extension, `@Composable`), свойства, аннотации, primary-конструктор |
| `*.java` | базовый разбор для смешанных проектов: классы, record, поля, методы, extends/implements |
| `AndroidManifest.xml` | компоненты, intent-фильтры, разрешения, application-атрибуты (исходный текст, не бинарный AXML из `build/`) |
| `res/layout*/*.xml` | имя layout, корневой view, id (`@+id/...`), использованные строки, binding-класс |
| `res/values*/...` | строковые ресурсы: имя, значение (escaped-последовательности раскрываются), `translatable=false`; квалификатор каталога (локаль) |
| `res/navigation/*.xml` | destinations, startDestination, actions (`app:destination`), deep link'и |
| `build.gradle(.kts)`, `settings.gradle(.kts)` | модули, namespace, sdk, buildFeatures, buildTypes, flavors, зависимости |
| `gradle/libs.versions.toml` | версии и библиотеки |
| `gradle-wrapper.properties` | версия Gradle |

Не индексируются: `build/`, `.git`, `.gradle`, `.idea`, `node_modules`, `.kt-cache`, бинарные ресурсы (png, jar, apk…), файлы больше 3 МБ, symlink/junction на файлы и каталоги (включая внутренние). Сгенерированный код (Room `*_Impl`, Hilt-компоненты, KSP/KAPT-выход в `build/generated`) в индекс не входит. Итеративный обход не следует ссылкам; `read`/`patch`/`create` отдельно проверяют realpath существующего пути или ближайшего существующего родителя нового файла. Внешние пути и битые ссылки отклоняются; это не защита от конкурентной подмены файловой системы другим процессом.

## Модули

Список модулей берётся из `include(...)` в `settings.gradle(.kts)` или Groovy-вызова без скобок (`include ':app', ':core'`); при их отсутствии — каталоги с `build.gradle`. Файл относится к модулю по префиксу пути. `namespace` для резолва относительных имён манифеста (`.MainActivity`) берётся из `android.namespace` в `build.gradle` модуля.

## Роли классов

Определяются по аннотациям, супертипам и имени; используются в `info`, `impls`, `manifest`:

| Роль | Условие |
|---|---|
| activity / fragment | супертип заканчивается на `Activity` / `Fragment` |
| viewmodel | супертип заканчивается на `ViewModel` |
| service | супертип `Service` / `IntentService` / `LifecycleService` |
| receiver / provider | супертип `BroadcastReceiver` / `ContentProvider` |
| application | супертип `Application` или `@HiltAndroidApp` |
| database | супертип `RoomDatabase` |
| dao | аннотация `@Dao` |
| entity | аннотация `@Entity` (таблица: `tableName` или имя класса) |
| api | методы с `@GET/@POST/@PUT/@DELETE/@PATCH/@HTTP/@Multipart...` |
| di | аннотация `@Module` |
| repository | имя заканчивается на `Repository` или реализует `*Repository` |
| usecase | имя заканчивается на `UseCase` |
| impl | имя заканчивается на `Impl` |

## Рёбра графа

- `extends`/`implements` — супертипы из заголовка класса, только для типов, найденных в проекте.
- `inject` — параметры primary-конструктора, `@Inject`-свойства, параметры `@Provides`/`@Binds` в классах с `@Module`. Koin-модули без отдельного анализа: связи видны через `uses`.
- `uses` — любое упоминание простого имени класса в другом файле (import, поле, вызов, аннотация, generic). Ссылки из самого файла-владельца не считаются.
- `calls` — вызов верхнеуровневой функции: `name(` или trailing-lambda `name {` (стиль Compose).
- `binding` — файл использует binding-класс layout-файла (`ActivityLegacyBinding` → `activity_legacy.xml`).

Граф файловый: несколько классов в одном файле дают общий узел. Рёбра дедуплицируются по `(from, to, type)`, сохраняется самая ранняя строка; обновление выполняется через Map, без линейного поиска в массиве рёбер. `path` ищет кратчайший маршрут (по умолчанию по направлению рёбер; `undirected=true` — в обе стороны). Плотный граф может быть большим даже без дубликатов.

## Предметные операции: откуда данные

- `manifest`: XML-комментарии исключаются с сохранением номеров строк; закомментированные компоненты, разрешения и intent-фильтры не учитываются.
- `room`: сущности — классы с ролью `entity` (таблица из `tableName`), колонки — параметры primary-конструктора (PK — по `@PrimaryKey` параметра), SQL `@Query` склеивается из всех строковых литералов аннотации (конкатенация `"SELECT ..." + "WHERE ..."` поддерживается); таблицы в SQL сопоставляются по `FROM|JOIN|INTO|UPDATE|TABLE <имя>`; для `@Insert/@Update/@Delete/@Upsert` таблица выводится из типа параметра (`User` или `List<User>`).
- `di`: binding-методы — `@Provides`/`@Binds` в классах с `@Module`, включая вложенные companion object; `@Inject constructor` — аннотация сохраняется в декларации класса; соответствие типов — по базовому имени (без generic-аргументов и пакета).
- `nav`: маршруты — литеральные аргументы `composable("...")` и `startDestination` в kt, идентификаторы destinations в nav-xml; вызовы — `navigate("маршрут")` и `navigate(R.id.dest)` по сырому тексту kt (в комментариях могут быть ложные срабатывания); actions — `<action app:destination>` внутри тега назначения. Аргументы-переменные `navigate(someRoute)` не трекаются.
- `res`: значение строки — текст элемента `<string>` с раскрытием escaped-последовательностей (`\n`, `\'`, `\uXXXX`) и XML-сущностей; локаль — квалификатор каталога `values-*`. Проверка `missing` учитывает обычные локали и BCP47 (`b+es`, `b+sr+Latn+RS`), исключает конфигурации (`night`, `land`, `w600dp`…) и смешанные квалификаторы (`en-night`). Поиск использования — `R.string.имя` в kt/java и `@string/имя` в xml по сырому тексту.
- `api`: HTTP-метод — аннотация метода интерфейса, URL — первый строковый литерал аннотации (у `@HTTP` — из `method`/`path`); `baseUrl` — первый найденный литерал в `baseUrl("...")` по всем kt/java проекта (если Retrofit настраивается не литералом, а переменной — не найдётся).

## Кодировки

- UTF-8 (с BOM и без), UTF-16LE/BE, cp1251. Определение: BOM → валидность UTF-8 → cp1251.
- Кириллица в cp1251 типична для легаси; такие файлы видны в `info` с предупреждением.
- `read` читает с учётом кодировки, `patch` сохраняет кодировку, BOM и перевод строк (LF/CRLF); пустой `old` запрещён. `create` выбирает UTF-8 или преобладающую cp1251 для не-ASCII текста и преобладающие переводы строк; `enc=utf-16le|utf-16be` создаёт UTF-16 с BOM. Поддержаны только `utf-8`, `cp1251`, `utf-16le`, `utf-16be`.

## sig: jar и aar

Порядок поиска: параметр `jars` → переменная `KT_JARS` → `libs/` каждого модуля → `~/.gradle/caches/modules-2/files-2.1`. В gradle-кэше кандидаты фильтруются по сегменту пакета (класс `retrofit2.Retrofit` ищется в путях, содержащих `retrofit2`), поэтому первый поиск может занять секунды. Короткое имя разрешается через обычный импорт, alias или кандидатов wildcard-импортов; неоднозначный проектный контекст не моделируется, для точного запроса передавай полное имя. При нескольких версиях выбирается старшая исправная; параметр `jar` задаёт подстроку имени файла.

Границы EOCD, центральных/локальных заголовков, constant pool и атрибутов проверяются до чтения. Битые архивы, обрезанные `.class` и незавершённые Signature дают предупреждение и пропускаются; остальные кандидаты продолжают обрабатываться. ZIP-комментарий с ложным EOCD не скрывает настоящий каталог. Поддержаны stored/deflate, не поддержаны ZIP64, многотомные и шифрованные ZIP. Лимиты: архив 256 МиБ, распакованный `classes.jar` 128 МиБ, `.class` 16 МиБ, глубина generics 64, измерений JVM-массива не больше 255. Дескрипторы и Signature повторно используемых членов разбираются один раз на строку и контекст (поле/метод, descriptor/Signature); результат переиспользуется при выводе. Распаковка ограничена объявленным размером записи. CRC и семантика JVM-байткода полностью не проверяются.

Обход каталогов JAR не следует вложенным symlink/junction и ограничен глубиной 9 и 2000 кандидатами на поисковый запрос. Относительные `jars`/`KT_JARS` разрешаются от рабочей директории; корень каждого явно заданного каталога канонизируется до обхода, поэтому junction на корне сохраняет доступ к вложенным JAR. `libs/` через внешнюю ссылку игнорируется; внешний каталог допустим как явный `jars`/`KT_JARS` либо Gradle-кэш. Это намеренное исключение к ограничению исходников внутри `root`.

Разбор `.class` идёт напрямую, без JDK: constant pool, поля, методы, атрибуты `Signature` (generics) и `Deprecated`. Ограничения байткода:

- имена параметров не восстанавливаются — показываются `arg0, arg1...` (библиотеки редко собирают с `-parameters`);
- `suspend`-функции видны как обычные с дополнительным параметром-Continuation;
- synthetic-члены и `$`-члены (лямбды, inline-классы) скрыты;
- у Kotlin-классов property выглядит как приватное поле + геттер; показываются public/protected члены байткода.

## Ограничения парсера Kotlin

- Unicode-буквы/цифры в идентификаторах и backtick-имена поддержаны; enum-записи индексируются и без `;`. Деструктуризация пропускается как декларация, пустые имена не создаются.
- Анонимные объекты (`object : X {}` в выражениях) и объектные выражения не индексируются.
- Диапазон строк функций с expression body (`fun f() = ...`) заканчивается на строке перед следующей декларацией — приблизительно.
- Комментарии, строки и `${}`-шаблоны исключаются из анализа; `search` ищет по сырому тексту.
- Комплексные заголовки (generic-конструкторы с лямбда-дефолтами, делегирование `by` в заголовке класса) могут разбираться частично; при сомнении читай диапазон через `read`.
- Compose-вызовы распознаются по имени верхнеуровневой функции; одноимённые методы классов в `calls` не попадают.

## Кэш

`.kt-cache/index.json` — полный индекс, внутренняя схема `CACHE_VERSION = 2` (не версия релиза скилла). Инвалидация автоматическая: сравниваются размер, mtime и SHA-256 содержимого всех включённых файлов. При любом расхождении, старой схеме или повреждённом JSON индекс пересобирается целиком. Проверка хешей читает содержимое и при тёплом кэше; `search`/`res`/`api` могут повторно читать выбранные исходники. Инкрементальный парсинг не реализован.

При создании и повторном использовании кэша обеспечивается `.kt-cache/.gitignore` со звёздочкой. Если путь кэша ведёт наружу или недоступен, выдаётся предупреждение, работа продолжается со свежим индексом в памяти без записи туда. Папку нельзя читать агенту и не нужно добавлять в git.
