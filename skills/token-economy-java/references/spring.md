# token-economy-java: устройство и ограничения

Открывай этот файл, только если ответ скрипта непонятен или нужно понять, чего он не видит.

## Какие файлы входят в индекс

Файлы `.java` из `git ls-files` (учитывается `.gitignore`), без git — обход каталогов. Пропускаются `module-info.java`, `package-info.java`, файлы больше 2 МБ, а также каталоги сборки `target`, `build`, `out`, `bin` вне `src` (пакет с таким именем внутри `src` пропущен не будет), `.gradle`, `.idea`, `node_modules`. Тесты (`src/test`) входят в индекс с пометкой `test`. Конфигурация (`application*.yml|yaml|properties`, `bootstrap*`) и SQL читаются на лету, без кэша.

## Как определяется роль файла (метка в квадратных скобках)

По аннотациям главного типа файла: `controller` (`@RestController`, `@Controller`), `advice` (`@ControllerAdvice`), `service`, `repository` (`@Repository` или интерфейс, наследующий `…Repository<…>`), `config` (`@Configuration`, `@SpringBootApplication`), `entity` (`@Entity`, `@Embeddable`, `@MappedSuperclass`), `properties` (`@ConfigurationProperties`), `client` (`@FeignClient`, `@HttpExchange`), `mapper` (`@Mapper`), `component`, `test` (путь `src/test` или тестовые аннотации Spring). Иначе — вид типа: `class`, `interface`, `enum`, `record`, `@interface`.

## Как строятся связи

- Типы: имена из заголовков (`extends`, `implements`, `permits`), аннотаций, полей, параметров, generics и тела кода разрешаются по явным импортам, пакету файла и импортам с `*`; полные имена с пакетом (`com.acme.Foo`) разрешаются напрямую, вложенные типы приводятся к файлу внешнего класса. Статический импорт даёт связь на класс.
- Внедрение (`inject`): параметры единственного конструктора даже у не-бина (или конструктора с `@Autowired`/`@Inject`), поля с `@Autowired`/`@Inject`/`@Resource`, параметры методов с `@Bean`/`@Autowired`/`@Inject`, компоненты record-бинов (`@ConfigurationProperties` и стереотипы), поля Lombok `@RequiredArgsConstructor` (не-static final без инициализатора) и `@AllArgsConstructor` (не-static). Это эвристика по типам: qualifier, scope и активация контекста не вычисляются.
- Если одно и то же отношение встречается разными способами, берётся самое сильное: extends/implements, затем inject, затем uses. Узлы файловые, внутренние связи одного файла не показываются; внешние библиотечные типы не являются узлами.

`endpoints` ограничен 80 строками, `beans` — 70, `listeners` — 60. `config` показывает до 40 определений и 20 использований. `entities` в подробном режиме — до 8 сущностей и 15 методов каждого репозитория; без `query` при числе сущностей >12 возвращает обзор до 80 строк. Это текстовые ответы с маркерами сокращения, не JSON.

## Эндпоинты и константы

Путь собирается из пути класса (`@RequestMapping`, `@HttpExchange`) и пути метода (`@GetMapping`, `@PostMapping`, `@PutMapping`, `@DeleteMapping`, `@PatchMapping`, `@RequestMapping(method=…)`, `@GetExchange` и аналоги). Строковые константы вида `ApiPaths.USERS` и выражения `BASE + "/users"` разворачиваются, если константа `static final String` объявлена в проекте (поиск по имени `Класс.ИМЯ`). Неразрешённые части остаются в виде `{выражение}`. Клиент определяется по `@FeignClient` или Get/Post/Put/Delete/PatchExchange на методах; одного `@HttpExchange` класса недостаточно. `@FeignClient(path/url)` не добавляется к пути; результат не является полным URL клиента.

`table` читает SQL в каталогах `db`, `migration`, `migrations`, `flyway`, `sql`, а также путях с `schema` или окончанием `data.sql`. Выводит колонки/ключи CREATE и отдельно до 12 выдержек ALTER (до 80 символов), до 8 упоминаний Liquibase; ALTER не применяется к CREATE и порядок миграций не вычисляется. Для JPA без `@Table(name)` используется snake_case имени класса/`@Entity(name)`, не Hibernate naming strategy; поля с аннотациями на геттерах не моделируются.

## Конфигурация

YAML разбирается как подмножество: вложенные ключи, списки (`key[0]`), несколько документов через `---` (профиль берётся из `spring.config.activate.on-profile` или `spring.profiles`), блочные скаляры показываются как `<текстовый блок>`, не их содержимое. Профиль из имени `application-dev.yml`/`bootstrap-dev.yml` имеет приоритет над профилем документа. Ключи сопоставляются без учёта регистра, дефисов и подчёркиваний; точки сохраняются. Не учитываются: переменные окружения, Config Server, `spring.config.import`, значения из командной строки; приоритеты источников и итоговая активная конфигурация не вычисляются.

Скрываются значения ключей с `password`, `passwd`, `pwd`, `secret`, `token`, `credential`, `private-key`, `api-key`, `access-key`, `client-secret`, `salt`. Исключение — чистая ссылка `${ENV}` без значения по умолчанию; `${ENV:секрет}` скрывается. Этот же контракт действует для `search` по `application*`/`bootstrap*`: вложенные пути, списки и все строки секретных скаляров маскируются до формирования сниппета; совпадения считаются по исходным строкам. Inline-контейнер с чувствительными ключами скрывается целиком. Экранированные ключи YAML/properties декодируются для проверки. Секреты под нечувствительными ключами, в комментариях и обычных исходниках не гарантируются скрытыми; это не универсальный DLP-фильтр.

## sig

Источник — `.class` внутри jar или корневых `target/classes`/`build/classes/java/main`; доступного jar достаточно без сборки проекта. Пакеты jar кэшируются в `.jv-cache/jars.json` по размеру/mtime. `jars` заменяет `JV_JARS`; оба используют системный разделитель путей, относительные каталоги — от cwd. Остальные источники (Maven, Gradle, корневой `lib/`) сохраняются. Обход jar ограничен глубиной 9, исключает `-sources`, `-javadoc`, `-tests`, `-test-sources`; кандидат сортируется по числам полного пути, не по Maven/Gradle dependency resolution. `jar` — регистронезависимая подстрока полного пути.

Вложенные классы указываются через точку (`Outer.Inner`) или `$`. Не показываются private/package-private, synthetic/bridge и `<clinit>`; `all=true` включает только первые две группы. `member` сравнивается без учёта регистра, вывод до 120 строк описания. Классы `java.*`/`javax.*`, не найденные локально, читаются через `javap -public`; `member`/`all` туда не передаются. Код библиотеки не загружается и не исполняется.

Некорректные class-границы и Signature (включая усечённые generics, массивы, параметры и throws) дают диагностическую ошибку без неограниченного цикла. Проверяются границы EOCD/центрального каталога/локальных записей, размеры и CRC32; stored и deflate поддерживаются, ZIP64 и многотомные архивы — нет. Лимиты: 64 MiB на центральный каталог, 16 MiB на class-файл, 128 уровней generic-вложенности и 255 измерений массива. Битая версия пропускается ради следующей исправной с предупреждением (не более пяти на фазу). Если найденные кандидаты класса все повреждены — exit 1; при его отсутствии — текстовая подсказка и exit 0. При отсутствующем/повреждённом `cache.json` короткое имя разрешается по актуальным исходникам, без сырого ENOENT.

## Чего скрипт не видит

- Конфигурация бинов через XML, `@Import`, `@ComponentScan` с ограничениями и автоконфигурации: `beans` перечисляет все аннотированные классы проекта, не проверяя, попадают ли они в контекст.
- `@Bean`-методы в классах без `@Configuration` показываются, но условия их активации не вычисляются.
- Функциональные маршруты (`RouterFunction`), Kotlin и Groovy, сгенерированный код (MapStruct, QueryDSL, Lombok, `target/generated-sources`).
- Использование типов в строках (имена классов в XML, `Class.forName`, SpEL).
- Миграции Liquibase разбираются только как упоминания `tableName`; схема из `CREATE TABLE` — только для SQL-миграций.
- Несколько деклараторов в одном поле (`int a, b;`) записываются как одно поле (первое имя).

## Кэш

`.jv-cache/index.json` и `cache.json` (внутри `.gitignore` со звёздочкой). Размер/mtime и состав Java-файлов инвалидируют индекс; изменённые файлы перепарсиваются инкрементально. Изменение build-конфига при неизменных Java-файлах само по себе не инвалидирует тёплый индекс. `op=build` пересобирает узлы/связи, но использует parse-кэш совпадающих size/mtime; для полного перепарсинга после обновления анализатора удали `.jv-cache`. Gitignore не снимает уже отслеживаемые файлы с учёта.

Пути к исходникам, операциям записи и кэшу проверяются по реальному корню и всем существующим предкам: внешние и неразрешимые symlink/junction не допускаются, внутренние ссылки и `..foo.java` допустимы. При записи используются уникальные эксклюзивные временные файлы. Защита от конкурентной замены предков между проверкой и использованием пути не обещается. Инвалидация индекса по-прежнему основана на размере/mtime; восстановление файла с обоими прежними значениями и точность FAT/exFAT отдельно не проверены.
