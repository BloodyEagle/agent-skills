# graph: подробности

Загружай этот файл, только если ответ `graph` непонятен или нужно настроить корни пакетов.

## Какие файлы входят в граф

Все `.py` проекта. Список берётся из `git ls-files` (учитывает `.gitignore`), без git — обход каталогов. Исключаются: `.venv`, `venv`, `.env`, `site-packages`, `__pycache__`, `build`, `dist`, `*.egg-info`, кэши линтеров, а также любая папка с `pyvenv.cfg` — и в режиме обхода, и в git-режиме. Папка `env` исключается только при наличии в ней `pyvenv.cfg`, поэтому настоящий пакет `env/` в графе останется. Файлы крупнее 1 МБ пропускаются. Файл с синтаксической ошибкой остаётся в графе без связей (`graph stats` перечисляет такие).

Вид файла: `module`, `package` (`__init__.py`), `script` (есть `if __name__ == "__main__"`, в любом порядке операндов, в том числе вложенный в `try`/`with`), `test` (`test_*.py`, `*_test.py`, `conftest.py`, папки `tests/`).Вид файла: `module`, `package` (`__init__.py`), `script` (есть `if __name__ == "__main__"`), `test` (`test_*.py`, `*_test.py`, `conftest.py`, папки `tests/`).

## Имена модулей и корни пакетов

Корень пакетов — сам проект, а также `src/`, если папка есть. Другие корни задаются параметром `--src ПАПКА` (можно повторять; указывай одинаково при каждом вызове; можно ставить до или после команды). Файл `src/app/core.py` получает имена `app.core` и `src.app.core`, поэтому `import app.core` находится в проекте, а не считается внешним пакетом.

## Связи

Распознаются `import x.y`, `from x import y`, `from . import y`, `from ..pkg.mod import y`, `from x import *` и вызовы `importlib.import_module("x")` / `__import__("x")` с константой (имя `importlib` не должно быть переименовано).

| Вид | Когда | Пометка |
|---|---|---|
| runtime | импорт при загрузке модуля (включая `try/except ImportError`) | без пометки |
| lazy | импорт внутри функции, метода или lambda | `(lazy)` |
| types | импорт под `if TYPE_CHECKING:` | `(types)` |

Если один файл подключён разными видами, берётся самый сильный (runtime > lazy > types).

Для `from pkg import name`: если `pkg.name` — модуль, связь идёт на него; иначе на `pkg`. Для `import a.b.c` связь идёт на самый глубокий найденный модуль.

`graph deps` / `rdeps` с `--why` добавляют к каждой строке номер строки импорта в соответствующем файле (`L12`).

Внешние пакеты (не stdlib и не проект) перечислены в `external` у файла и в `graph stats`. На Python 3.9 список stdlib-имён восстанавливается приблизительно — по содержимому каталога стандартной библиотеки.

## Циклы и пути

`graph cycles` считает только runtime-связи. Циклы через lazy и types не показываются: они не ломают загрузку модулей. Большие группы выводятся выборкой.

`graph path` ищет цепочку по всем видам связей (это зависимости на уровне исходников, не обязательно загрузка) и помечает переходы (`lazy`)/(`types`).

## symbol

Принимает простое имя (`run`), составное (`Engine.run`) или полное (`app.core.Engine`); имён можно передать несколько. Находит классы, функции, методы (`Класс.метод`), модульные переменные и константы, включая определённые внутри `if`/`try`/`with`/`for`/`while` на верхнем уровне. Вложенные функции и атрибуты классов не индексируются.

## Кэш

`token-economy/graph.json` и `cache.json`. Внутри лежит `.gitignore` со звёздочкой, поэтому в `git` ничего не попадает. Перестроение запускается само при изменении, добавлении, удалении и переименовании файлов; разбираются только изменённые файлы. Принудительно: `graph build`. При смене формата кэша (версия хранится внутри файлов) перестроение тоже происходит само.

## sig

Находит источник имени по `sys.path`, корню проекта (включая `src/` и дополнительные корни из `--src`) и `.venv` / `venv` / `env`, затем разбирает его через `ast`, не импортируя и не исполняя (для встроенных модулей вроде `sys` и `math` — через `inspect`). Идёт по реэкспортам (`from .api import get`, `from ._impl import *`), псевдонимам модулей (`os.path`) и базовым классам из того же модуля. Подхватывает `.pyi`-стабы, если они есть; скомпилированные `.so/.pyd` помечает как «без исходников» вместо ложного «не найдено».
