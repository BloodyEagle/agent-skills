# token-economy-py

Один скрипт `te.py` (только стандартная библиотека, Python 3.9+) с командами `graph` (включая `graph build`), `outline`, `search`, `sig` и `info` (плюс `selftest` для самопроверки скрипта). Вывод — короткий текст. По умолчанию корень проекта — текущий каталог; иначе добавь `--root ПУТЬ`. Корень должен существовать и быть каталогом: неверный `--root` даёт ошибку с exit1, не создавая каталог или кэш. На Windows вместо `python3` — `python`.

При доступной MegaMemory применяй общий порядок из `rules/RULES.md`, раздел «megamemory»; без неё выполняй обычную навигацию. Память не заменяет актуальные graph/outline и чтение перед правкой. CLI отдельный, не TS key=value и не общий dispatcher.

Вызов: python -I -B "<SCRIPTS_DIR>\te.py" <команда> …

Изолированный `-I` обязателен; `-B` предотвращает запись bytecode. Cwd (рабочий каталог) для искусственного/недоверенного проекта держи вне анализируемого каталога, вызывай доверенный `te.py` по абсолютному пути и передавай проект через `--root`. Не запускай интерпретатор или скрипты из скачанного каталога.

`<SCRIPTS_DIR>` — папка `scripts` этого скилла: возьми полный путь этого SKILL.md и замени имя файла на `scripts`. Каталог скиллов агента: ZCode — `%USERPROFILE%\.zcode\skills\…` (в репозитории проекта — `.zcode\skills\…`), Kilo Code — `%USERPROFILE%\.kilocode\skills\…` или `~/.config/kilo/skills/…` (в репозитории — `.kilo\skills\…`).

Общие параметры `--root` и `--src` можно указывать как до команды, так и после неё.

## Правила

1. Один раз за разговор вызови info: версия python и зависимости, состав файлов, src-корни, крупнейшие файлы.
2. Файл короче 300 строк читай напрямую — вызов скрипта дороже возможной экономии.
3. Файл от 300 строк: сначала outline, затем читай только нужный диапазон строк (в выводе L12-80).
4. Где определён класс, функция, метод или константа — graph symbol. Где встречается текст — search; если нужны только файлы с совпадениями — search -l.
5. Перед правкой общего модуля вызови graph rdeps (с --why — ещё и номер строки импорта): увидишь, кто его импортирует; файлы с пометкой [test] — тесты, которые стоит запустить.
6. Аргументы и сигнатуру функции стороннего пакета или stdlib узнавай через sig. Не читай исходники библиотек, не угадывай параметры и не вызывай help().
7. Правь штатным инструментом замены фрагмента. Файл длиннее 50 строк, если правка затрагивает менее 30% строк, целиком не перезаписывай.
8. Граф обновляется сам при каждом вызове. Папку .token-economy/ не читай.
9. `graph`, `outline` и `search` проверяют реальные пути, включая symlink/junction и родительские сегменты `..`. Явный путь с выходом за корень отклоняется; обход пропускает внешние ссылки. Внутренние ссылки разрешаются в канонический путь без дубликатов. `--path` у `search` остаётся относительным. Кэш также не читается и не записывается через внешние ссылки.
10. Запросы и значения с пробелами, звёздочками и скобками (--ext, --re, --path) бери в кавычки.

## Команды

Ниже TE = python -I -B "<SCRIPTS_DIR>\te.py". Глубина --depth ограничена 5.

| Задача | Команда |
|---|---|
| Где определено | `TE graph symbol Engine · TE graph symbol Engine.run · TE graph symbol app.models.User · несколько имён сразу: TE graph symbol Engine User` |
| Что импортирует файл | `TE graph deps src/app/core.py --depth 2` |
| Кто импортирует файл | `TE graph rdeps src/app/core.py --depth 2 --why` |
| Цепочка между файлами | `TE graph path scripts/deploy.py src/app/models.py` |
| Сводка по файлу | `TE graph node core` |
| Циклические импорты | `TE graph cycles` |
| Обзор проекта | `TE graph stats` |
| Явно пересобрать граф | `TE graph build` — пересчитывает связи; AST неизменённых файлов использует из кэша |
| Оглавление файла | `TE outline src/app/core.py` (`--docs` — с первой строкой docstring) |
| Поиск текста | `TE search "имя" --ext .py,.yaml -i` · `--re` регулярка · `--path src/app` · `--limit 50 -l` только список файлов |
| Сигнатура библиотеки | `TE sig requests.get` · `TE sig pathlib.Path.glob` · `TE sig json.dumps --doc` |
| Паспорт проекта | `TE info` — python, зависимости (pyproject/requirements), состав файлов, src-корни, крупнейшие файлы |

Файл в `graph` можно задать путём, частью пути, именем модуля (`app.core`) или именем файла. При неоднозначности скрипт вернёт список кандидатов.

## Что показывает вывод

- CLI не выдаёт JSON: `search` positive — имя файла, строки `N: text`, итог `-- совпадений: N, файлов: M`; no-match — `«query»: совпадений нет (N файлов просмотрено)`, exit0. При `--limit` итог добавляет `показано K`: это усечение, не полный ответ.
- Неверная search regex — `Ошибка: ...` в stdout, exit1; ошибки argparse — stderr/exit2. Пустой stdout не считать no-match. `graph path` negative — `цепочки a.py → b.py нет`, exit0; свободный query не заменяет два endpoint.
- Машинного общего completeness flag нет: перед выводом об отсутствии зависимостей проверяй `graph stats`, синтаксические ошибки, source roots и ограничения ниже. Для benchmark text adapter должен распознавать этот формат и expected positives/negatives, не только exit0.
- `deps` / `rdeps`: строки вида `уровень путь [вид]`. Вид: `[test]`, `[script]` (есть `__main__`), `[package]` (`__init__.py`). Пометки `(lazy)` — импорт внутри функции, `(types)` — только под `TYPE_CHECKING`; в циклах они не участвуют. С `--why` в конце — номер строки импорта (`L12`).
- `symbol`: `имя  вид  путь:строка_начала-строка_конца`, сразу готово для точечного чтения.
- `path`: цепочка `a.py → b.py → c.py`; переходы (`lazy`)/(`types`) помечены.
- `sig`: сигнатура, первая строка docstring и путь к источнику; для класса — публичные методы. Исходный код не исполняется (встроенные модули вроде `sys`/`math` разбираются через `inspect`).

## Ограничения

- `search` пропускает файлы крупнее 1 МБ и бинарные; текст ищется как utf-8 (не-utf8 — с фолбэком на cp1251).
- `search` не маскирует секреты: совпавшая строка конфигурации может содержать пароль, токен или ключ. Не ищи реальные секретные значения; ограничивай `--path`/`--ext`, используй `-l`, если нужны только имена файлов. Перед передачей вывода удаляй секреты; `.gitignore` не заменяет маскирование.
- Динамические импорты учитываются только для `importlib.import_module("pkg.mod")` / `__import__("pkg.mod")` с константой и без переименования `importlib`.
- Атрибуты, создаваемые во время выполнения, `sig` не найдёт; у скомпилированных модулей (`.so`, `.pyd`) исходников нет — скрипт так и сообщает; `.pyi`-стабы используются, если есть.
- Для `sig` стороннего пакета нужна его установка в интерпретаторе скрипта или в `.venv` / `venv` / `env` проекта (подхватываются автоматически).
- Подробности про модули, виды связей и корни пакетов: `references/graph.md`.
