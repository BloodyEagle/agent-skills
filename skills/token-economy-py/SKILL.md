# token-economy-py

Один скрипт `te.py` (только стандартная библиотека, Python 3.9+) с командами `graph`, `outline`, `search` и `sig` (плюс `selftest` для самопроверки скрипта). Вывод — короткий текст. Запускай из корня проекта; иначе добавь `--root ПУТЬ`. На Windows вместо `python3` — `python`.

Вызов: python3 "${HERMES_SKILL_DIR}/scripts/te.py" <команда> …

Общие параметры `--root` и `--src` можно указывать как до команды, так и после неё.

## Правила

1. Файл короче 300 строк читай напрямую — вызов скрипта дороже возможной экономии.
2. Файл от 300 строк: сначала outline, затем читай только нужный диапазон строк (в выводе L12-80).
3. Где определён класс, функция, метод или константа — graph symbol. Где встречается текст — search; если нужны только файлы с совпадениями — search -l.
4. Перед правкой общего модуля вызови graph rdeps (с --why — ещё и номер строки импорта): увидишь, кто его импортирует; файлы с пометкой [test] — тесты, которые стоит запустить.
5. Аргументы и сигнатуру функции стороннего пакета или stdlib узнавай через sig. Не читай исходники библиотек, не угадывай параметры и не вызывай help().
6. Правь штатным инструментом замены фрагмента. Файл длиннее 50 строк, если правка затрагивает менее 30% строк, целиком не перезаписывай.
7. Граф обновляется сам при каждом вызове. Папку .token-economy/ не читай.
8. graph, outline и search работают только внутри проекта; пути вне проекта отклоняются.
9. Запросы и значения с пробелами, звёздочками и скобками (--ext, --re, --path) бери в кавычки.

## Команды

Ниже TE = python3 "${HERMES_SKILL_DIR}/scripts/te.py". Глубина --depth ограничена 5.

| Задача | Команда |
|---|---|
| Где определено | `TE graph symbol Engine · TE graph symbol Engine.run · TE graph symbol app.models.User · несколько имён сразу: TE graph symbol Engine User` |
| Что импортирует файл | `TE graph deps src/app/core.py --depth 2` |
| Кто импортирует файл | `TE graph rdeps src/app/core.py --depth 2 --why` |
| Цепочка между файлами | `TE graph path scripts/deploy.py src/app/models.py` |
| Сводка по файлу | `TE graph node core` |
| Циклические импорты | `TE graph cycles` |
| Обзор проекта | `TE graph stats` |
| Оглавление файла | `TE outline src/app/core.py` (`--docs` — с первой строкой docstring) |
| Поиск текста | `TE search "имя" --ext .py,.yaml -i` · `--re` регулярка · `--path src/app` · `--limit 50 -l` только список файлов |
| Сигнатура библиотеки | `TE sig requests.get` · `TE sig pathlib.Path.glob` · `TE sig json.dumps --doc` |

Файл в `graph` можно задать путём, частью пути, именем модуля (`app.core`) или именем файла. При неоднозначности скрипт вернёт список кандидатов.

## Что показывает вывод

- `deps` / `rdeps`: строки вида `уровень путь [вид]`. Вид: `[test]`, `[script]` (есть `__main__`), `[package]` (`__init__.py`). Пометки `(lazy)` — импорт внутри функции, `(types)` — только под `TYPE_CHECKING`; в циклах они не участвуют. С `--why` в конце — номер строки импорта (`L12`).
- `symbol`: `имя  вид  путь:строка_начала-строка_конца`, сразу готово для точечного чтения.
- `path`: цепочка `a.py → b.py → c.py`; переходы (`lazy`)/(`types`) помечены.
- `sig`: сигнатура, первая строка docstring и путь к источнику; для класса — публичные методы. Исходный код не исполняется (встроенные модули вроде `sys`/`math` разбираются через `inspect`).

## Ограничения

- `search` пропускает файлы крупнее 1 МБ и бинарные; текст ищется как utf-8 (не-utf8 — с фолбэком на cp1251).
- Динамические импорты учитываются только для `importlib.import_module("pkg.mod")` / `__import__("pkg.mod")` с константой и без переименования `importlib`.
- Атрибуты, создаваемые во время выполнения, `sig` не найдёт; у скомпилированных модулей (`.so`, `.pyd`) исходников нет — скрипт так и сообщает; `.pyi`-стабы используются, если есть.
- Для `sig` стороннего пакета нужна его установка в интерпретаторе скрипта или в `.venv` / `venv` / `env` проекта (подхватываются автоматически).
- Подробности про модули, виды связей и корни пакетов: `references/graph.md`.
