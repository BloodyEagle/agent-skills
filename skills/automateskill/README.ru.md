# automateskill

[English version](README.md)

> **Работает только в ZCode:** требует `CronCreate` и пул субагентов `.zcode/agents`. В других агентах (Claude Code, Kilo Code и т.п.) шаги выполнить не сможет.

Превращает сообщение вида «в 03:00 запусти задачу: в репозитории X проанализируй код моделью Y, сохрани отчёт и напиши план исправления, затем моделью Z выполни этот план в ветке Q — каждый пункт отдельный коммит, запушь в git» в два артефакта: план-файл с frontmatter в `tasks/input/<slug>/` runner-репозитория и выделенную автоматизацию `CronCreate`, которая выполняет планы своей папки зарегистрированными субагентами.

## Как работает

1. **Извлеки параметры** из текста: расписание, повторение (разово, если повторение не указано), целевой репозиторий, путь локальной копии, исполнители фаз (модели), фоллбек-модель, ветка (по умолчанию `obs/<имя-плана>`), суть работы. Модели-исполнители берутся только из описания пользователя; модель не названа или недоступна — полный список моделей предлагается через `ListModels`, без выбора скилл не продолжает. Фоллбек (включая «без фоллбека») спрашивается отдельно от исполнителей фаз.
2. **Проверь окружение:** runner-репозиторий с подтверждённой `main` (шаблоны поддерживают только `main`; другая основная ветка — остановка и вопрос), определения исполнителей в `.zcode/agents/` текущего workspace и права на push в целевой репозиторий — всё до создания плана. Без прав на push скилл сначала запрашивает авторизацию, затем предлагает форк только с согласия; работа через форк остаётся в форке, PR в апстрим — вручную.
3. **Создай план-файл** `tasks/input/<slug>/00-<краткое-имя>.md` с frontmatter (`repo`/`repo-path`, `worktree`, `executor`, `branch`), закоммить и запушь его в runner.
4. **Создай автоматизацию** через `CronCreate`: `delayMinutes` для относительной задержки («через 2 часа»), `intervalUnit` + `interval` (1–200) для «каждые N минут/часов/дней/…», cron в локальной зоне машины для календарного повторения, закреплённая календарная дата с `recurring: false` для разового абсолютного запуска («18 ноября в 03:00») — дата согласовывается с пользователем при неоднозначности.
5. **Проверь и отчитайся:** `CronList` показывает статус `active` и время следующего запуска; в ответе — id автоматизации, следующий запуск, путь план-файла, исполнители и папка, куда падают отчёты (по умолчанию `tasks/done` целевого репозитория).

## Примечания

- В `title` сохраняется формулировка времени пользователя; модель самой автоматизации — дефолтная хоста, чинится в UI Automations.
- `CronCreate` сам по себе не архивирует, не пишет отчёты, не коммитит и не мержит — эти шаги должны быть предписаны в определениях агентов-исполнителей; неподходящий контракт ветки останавливает план до публикации.
- Ошибка push во время ночного выполнения остановит план (STOPPED) с отчётом; поэтому права на push проверяются до создания плана.
- Лимит механизма — 10 планов за запуск; цепочка фаз не должна зацикливаться (план порождает план порождает план…).
- Не удаляй workspace, к которому привязана автоматизация.
