# Шаблон промпта выделенной автоматизации (CronCreate)

Подстановки при использовании:
- `<REPO_PATH>` — путь runner-репозитория (обычно `C:\p\agent-skills`);
- `<PLANDIR>` — папка планов этой автоматизации (`<REPO_PATH>\tasks\scheduled\<slug>`);
- `<EXECUTORS>` — допустимые имена агентов через ` | ` в порядке чередования: основной исполнитель первым, фоллбек (если задан пользователем) вторым; без фоллбека — одно имя;
- `<MODELS>` — соответствие агентов и моделей (например `plan-executor → new-provider-2/gpt-6-astra` или `executor-mistral → openrouter/mistral-x$high`);
- `<TITLE>` — название задачи для сводок.

---

```text
Отложенная обработка планов agent-skills (выделенная автоматизация «<TITLE>»).

Runner-репозиторий: <REPO_PATH> (remote https://github.com/BloodyEagle/agent-skills.git), ветка main. Папка планов этого запуска: <PLANDIR>. Разрешённые исполнители: <EXECUTORS>. Модели: <MODELS>.

1. Обнови runner: git -C <REPO_PATH> pull --ff-only origin main. Если pull не удался — заверши запуск, описав ошибку.
2. Работай циклом: повторяй шаги 3-7, пока остаются необработанные планы, но не более 10 планов за весь запуск (сгенерированные субагентами планы тоже считаются). После каждого выполненного плана заново сканируй <PLANDIR> — в ходе запуска могут появляться новые планы.
3. Составь список md-файлов в <PLANDIR>: только файлы вида NN-*.md, где NN — число. Файлы с префиксом STOPPED- и подпапки игнорируй. Если подходящих файлов нет — заверши запуск итоговой сводкой.
4. Возьми файл с наименьшим числовым префиксом и прочитай его. Если файл начинается с ограждения frontmatter (--- ... ---), разбери поля:
   - repo: <URL> — целевой репозиторий. Локальная копия: путь из поля worktree, если указан, иначе C:\Users\KuninAA\.zcode\repos\<имя-репо-из-URL-без-.git>. Если копии нет — git clone <URL> <путь> (создай родительский каталог); если есть — git -C <путь> pull --ff-only origin main. Основная ветка целевого репозитория — main.
   - repo-path: <путь> — использовать существующую локальную копию; git -C <путь> pull --ff-only origin main.
   - executor: имя агента из списка разрешённых.
   Если frontmatter нет или в нём нет ни repo, ни repo-path — целевой репозиторий: сам runner (REPO = <REPO_PATH>, REPO_URL = -).
5. Некорректный план (executor вне списка разрешённых): в runner переименуй <относительный путь файла> в STOPPED-<имя>.md (в той же папке), создай <REPO_PATH>\tasks\done\<имя>.report.md с причиной (что именно некорректно в frontmatter), один коммит tasks/scheduled/<slug>: ОСТАНОВЛЕН, требует внимания, git push origin main. Затем останови весь запуск и выведи сводку.
6. Запусти субагента. Политика ошибок модели/провайдера (квота, rate limit, недоступность провайдера, сетевая ошибка) — по варианту, соответствующему числу агентов в <EXECUTORS>:
   - **С фоллбеком** (несколько агентов в <EXECUTORS>): максимум 3 итерации, исполнители чередуются по кругу в порядке <EXECUTORS>, начиная с указанного в плане. При ошибке модели/провайдера — следующий по кругу. Всего не более 6 попыток. Все попытки исчерпаны ошибками — прекрати весь запуск: план не выполнен, выведи все ошибки попыток и что требует внимания.
   - **Без фоллбека** (один агент в <EXECUTORS>): одна попытка. Ошибка модели/провайдера завершает весь запуск со сводкой (какой план не выполнен, текст ошибки, что требует внимания); план-файл оставь в <PLANDIR> — следующий запуск подхватит его снова.
   - В промпт субагента передай строки: PLAN — полный путь к файлу плана; PLAN_NAME — имя файла без .md; REPO — путь локальной копии целевого репозитория; REPO_URL — URL целевого репозитория, или - если целевой — runner; BRANCH — из frontmatter плана, если есть, иначе obs/<PLAN_NAME>; PLANDIR — <PLANDIR>.
   - Успешный запуск субагента, который сам сообщил об остановке плана по своим правилам (STOPPED-маркировка), — это НЕ ошибка модели: перезапуски другим исполнителем не применять. STOPPED означает остановку всего запуска: оставшиеся планы, включая сгенерированные, не выполнять.
7. После успеха субагента (архив плана и отчёта в целевом репозитории и уборка план-файла из runner сделаны им самим) вернись к шагу 2.
8. Итог запуска — краткая сводка: какие планы выполнены (целевые репозитории, коммиты, пути отчётов, число попыток, сгенерированные новые планы), какие остановлены и почему, что требует внимания пользователя.

Запрещено: force-push, удаление веток и коммитов, работа с файлами вне <REPO_PATH> и локальных копий целевых репозиториев из frontmatter, включение в коммиты незатреканных файлов, не относящихся к задаче (.kilo/, AUDIT-*.md, REPORT.md и т.п.), клонирование любых репозиториев, кроме указанных в frontmatter планов этого запуска.
```

## Заметки для скилла (не попадают в промпт)

- Ночная автоматизация 03:01 сканирует только `tasks\obs` — папки `tasks\scheduled\<slug>` ей не видны, конфликтов двойного выполнения нет.
- Модель и уровень самой автоматизации через CronCreate не задаются: работает дефолт хоста. Ошибка «Automation 模型选择不可用，请重新选择模型与思考档位» = переВыбрать модель/уровень в UI (Automations → настройки задачи).
- Новые файлы агентов в `.zcode/agents/` регистрируются на старте свежей сессии; правки уже зарегистрированных в живой сессии не подхватываются.
- Если в `<EXECUTORS>` добавляется новый агент — сначала убедись, что его файл существует в workspace и модель указана с `$уровень`.
