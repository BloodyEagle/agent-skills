# automateskill — отложенная задача из свободного описания

> **Скилл работает только в ZCode.** Он опирается на инструменты ZCode: `CronCreate` (персистентные автоматизации по расписанию), `ListModels`, субагентов из `.zcode/agents/` с моделями вида `провайдер/модель$уровень`. В других агентах (Claude Code, Kilo Code, Codex, Gemini CLI и т.п.) скилл загрузится, но шаги выполнить не сможет — там нет этих механизмов.

Превращает сообщение вида «в 03:00 запусти задачу: в репозитории X проанализируй код моделью Y, сохрани отчёт и напиши план исправления, затем моделью Z выполни этот план в ветке Q — каждый пункт отдельный коммит, отчёт сохрани, запушь в git» в два артефакта:

1. **План-файл** с frontmatter в runner-репозитории: `C:\p\agent-skills\tasks\scheduled\<slug>\00-<краткое-имя>.md`.
2. **Выделенная автоматизация** (`CronCreate`) на указанное время, которая выполняет планы из своей папки зарегистрированными субагентами.

Папка `tasks/scheduled/<slug>/` изолирована от `tasks/obs` — ночная автоматизация 03:01 не захватит эти планы.

## Шаг 1. Извлеки параметры из текста

| Параметр | Примеры формулировок | По умолчанию |
|---|---|---|
| Расписание | «в 03:00», «каждый день в 9», «через 2 часа», «по будням в 21:30» | спросить |
| Повторение | «запусти» (разово) / «ежедневно», «каждый день» | спросить |
| Целевой репозиторий | «в репозитории X», URL, локальный путь | спросить |
| Путь локальной копии | «копия в C:\p\…» | клон в `C:\Users\KuninAA\.zcode\repos\<имя>` |
| Исполнитель фазы 1 (модель Y) | «проанализируй моделью Y» | `plan-executor` |
| Исполнитель фазы 2 (модель Z) | «выполни план моделью Z» | берётся из frontmatter сгенерированного плана (фаза 1 предписывает его создать) |
| Ветка | «в ветке Q» | `obs/<имя-плана>` |
| Суть работы | свободный текст | — |

Соответствие моделей и агентов пула: `gpt-6-astra`/«астра» → `plan-executor`; `gpt-6.1-sol`/«сол» → `plan-executor-sol`. Отчёт по умолчанию пишется в `tasks/done` целевого репозитория — спрашивать, только если пользователь хочет иначе.

## Шаг 2. Проверь окружение

1. Runner существует: `C:\p\agent-skills`. Нет — спроси актуальный путь.
2. **Текущий workspace** содержит `.zcode/agents/plan-executor.md` и `plan-executor-sol.md`? Автоматизация привяжется к текущему workspace и будет порождать только его агентов. Если файлов здесь нет — остановись и спроси: выполнить скилл в workspace с агентами (там, где они зарегистрированы) или скопировать определения агентов в текущий workspace.
3. Пользователь назвал модель вне пула: проверь её существование и уровни через `ListModels`. Модель есть — предложи создать нового агента-исполнителя: копия `plan-executor.md` с `name: executor-<короткое-имя>` и `model: <провайдер>/<модель>$<уровень>` в `.zcode/agents/` текущего workspace (напомни: новый агент зарегистрируется для свежих сессий — автоматизация, созданная сейчас, заработает с ним; правки уже зарегистрированных агентов в живой сессии не подхватываются). Модели нет — сообщи и предложи выбор из существующих.

## Шаг 3. Доспроси недостающее

Собери недостающее через `AskUserQuestion` одним батчем (до 4 вопросов: расписание, репозиторий, исполнители, ветка). Один-два коротких вопроса можно задать текстом. Не придумывай значения сам.

## Шаг 4. Проверь права на push; нет прав — запроси авторизацию; чужое — форк

Репозиторий известен после шагa 3. Проверь до создания плана — план, который ночью упадёт на push, остановится с STOPPED и потеряет запуск.

1. Проверка прав:
   - Локальная копия (`repo-path`): `git -C <путь> push --dry-run origin main` прошёл без ошибки авторизации → права есть.
   - GitHub URL: `gh api repos/<owner>/<repo> --jq .permissions.push` → `true` / `false` (ошибка 404 у приватного репозитория = прав нет).
   - `gh` не установлен или не авторизован — это тоже «прав нет», переходи к п. 2. Проверка клоном (`git clone --depth 1` + `git push --dry-run`) — только быстрая диагностика, не замена авторизации.
2. Прав нет — **запроси авторизацию у пользователя** и дождись её:
   - GitHub: попроси пользователя выполнить в терминале `gh auth login` (интерактивный вход от имени агента выполнить нельзя). Для чистого git-ремоута — добавить учётные данные в Git Credential Manager (например, один раз сделать push вручную).
   - После подтверждения пользователя («готово») повтори проверку из п. 1.
3. Права появились → репозиторий считается своим: работаем с оригиналом, форк не нужен.
4. Права так и не появились → чужой репозиторий: `gh repo fork <owner>/<repo> --clone=false` (если форк уже существует, gh сообщит — используй его). URL форка: `https://github.com/<твой-логин>/<repo>.git`. Форк может отставать от апстрима — синхронизируй при необходимости: `gh repo sync <твой-логин>/<repo> --branch main`. Пользователю скажи явно: «пуш будет в твой форк <URL>; в апстрим изменения не попадут — PR с форка вручную». Если пользователь против форка — останови скилл, план не создавай.
5. В frontmatter плана итоговый репозиторий (оригинал или форк) подставь в `repo:` (или `repo-path:` на его локальную копию) — вся механика (ветки, merge в main, архив, push) дальше работает без изменений.

## Шаг 5. Создай план-файл

Прочитай `references/plan-template.md` и следуй ему: frontmatter (`repo`/`repo-path`, `worktree`, `executor`, `branch`) + тело задачи по пунктам. Многофазную задачу («анализ → план исправлений → выполнение») оформи по разделу «Цепочка фаз» шаблона: тело фазы 1 предписывает исполнителю составить следующий план в эту же папку с `executor:` модели Z.

Слаг папки — латиница, цифры, дефис (например `code-audit-myrepo`).

## Шаг 6. Закоммить план в runner

```bash
git -C C:/p/agent-skills add tasks/scheduled
git -C C:/p/agent-skills commit -m "tasks/scheduled: план <slug> (<краткая суть>)"
git -C C:/p/agent-skills push origin main
```

Push упал — остановись и сообщи: без пула автоматизация не сможет даже забрать план.

## Шаг 7. Создай автоматизацию

Прочитай `references/automation-prompt.md`, подставь `<REPO_PATH>`, `<PLANDIR>`, `<EXECUTORS>`, `<MODELS>` и передай `CronCreate`:

- `cron` — по расписанию из шага 1 в **локальной зоне** машины (проверь `tzutil //g`; «03:00» при зоне MSK → `0 3 * * *`). Разовый запуск «через N минут» — `delayMinutes`.
- `recurring: true` для повторов; разовая задача — `recurring: false`.
- `title` — сохрани формулировку времени пользователя: «<его фраза про время>: <slug>».

## Шаг 8. Проверь и отчитайся

`CronList`: статус `active`, корректный `nextRunAt`. В ответе пользователю: id автоматизации, время следующего запуска, путь план-файла, список исполнителей, куда упадут отчёты. Предупреждения (коротко, всегда):

- Модель самой автоматизации — дефолтная хоста; ошибка «Automation 模型选择不可用…» чинится только в UI (Automations → настройки задачи → выбрать модель и уровень).
- `reasoning-level-missing` у субагентов означает, что в `model:` агента нет `$уровень`.
- Не удалять workspace, к которому привязана автоматизация.

## Ограничения

- Исполнитель — только из файлов `.zcode/agents/` текущего workspace; «модель X» вне пула требует создания агента (шаг 2).
- Права на push проверяются скиллом до создания плана (шаг 4); при отсутствии прав запрашивается авторизация пользователя, затем — форк. Ошибка push во время ночного выполнения всё равно возможна (права отозваны, сеть) — план остановится (STOPPED) с отчётом.
- Работа с форком не попадает в апстрим: изменения живут в вашем форке; PR в оригинал — вручную.
- Лимит механизма — 10 планов за запуск; цепочка фаз не должна зацикливаться (план порождает план порождает план…).
