# Экономия токенов (скилл token-economy)

    Первым действием в любой задаче вызывай git-check из скилла token-economy — получи список файлов с незакоммиченными правками.
	Навигацию выполняй через graph-операции скилла: определения символов и селекторов (op: symbol/selector), зависимости и потребителей файла (op: deps/rdeps), связи файлов (op: path). search и чтение файлов — только для деталей реализации.
    Чтение файлов, поиск, анализ и все правки выполняй только инструментами скилла token-economy. Пороги применимости (размер файла, объём правок)описаны в SKILL.md — следуй им.
    Тебе строго запрещено перезаписывать файл целиком, когда по порогам скилла применим patch (правки менее 30% файла).
    Сущности Angular (компоненты, сервисы, пайпы, модули, директивы,гварды) создавай только через generate, заготовки руками не пиши.
    Перед патчем файла из списка git-check сначала прочитай его актуальнуюверсию инструментами скилла: oldChunk должен соответствовать текущему состоянию файла, а не последнему коммиту.
    Не запускай компиляцию, линтер, тесты, полный билд и ng serve — об ошибках я сообщу сам.

# Долговременная память (hindsight)

    Вопросы структуры проекта (что где лежит, кто от кого зависит) закрывай графом, не памятью: граф всегда актуален, 
    записи памяти устаревают. В начале нетривиальной задачи в малознакомой части проекта — один recall по теме задачи.
    Если запись памяти ссылается на файлы или зависимости — проверь её графом, прежде чем опираться. Retain: решения 
    с обоснованием, конвенции, мои поправки, явные «запомни». Не retain: списки файлов, зависимости, содержимое кода.
    Банк памяти один на проект; новые банки не создавай без моего разрешения.Память обновляй по смысловым событиям, а не 
    по диффам: переименовал или удалил модуль/папку — обнови записи domain-map и structure, где он упомянут; устранил ловушку 
    из gotchas — удали эту запись; сменилась конвенция или архитектура — добавь новую запись.Обычные правки и рефакторинг 
    памяти не касаются: фактов, привязанных к файлам и зависимостям, в памяти нет — их отдаёт граф.Решения не перезаписывай: 
    смена подхода — новая запись, а не правка старой.Для обновления используй recall по тегу компонента → delete по id → retain заново.
