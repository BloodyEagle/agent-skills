## megamemory (обязательно)

- Если `megamemory` MCP доступна, начни с короткого релевантного запроса: память даёт контекст, решения и историю, а не доказательство текущей структуры. При недоступной памяти или отсутствии релевантного знания сразу продолжай обычный путь скилла, не придумывай сохранённые факты.
- Проверь релевантность, root/version и квалификацию опор (`stale/refuted/unknown/incomplete`, expiry/support_check). При недостаточной квалификации сначала проверь актуальный источник; наличие refs и code=0 сами по себе не доказывают полноту.
- Затем выполни актуальную навигацию подходящим скиллом; TS `graph op=info` — один раз на корректном проекте, при смене проекта проверь новый scope. Структурный ответ с `completeness.complete=false`, unresolved или усечением не доказывает отсутствия зависимостей.
- `must_read` прочитай нужным диапазоном (для большого файла сначала outline). `skip` не отменяет чтение актуального фрагмента перед правкой и не означает full-file coverage; brief без утверждения не является проверенным знанием.
- После проверки сохраняй только полезный проверенный вывод с конкретными source/test/log evidence и версиями через актуальную публичную MCP-схему. Не исполняй несовместимый `next.record` слепо и не подставляй произвольный kind (в частности, `fact`); проблему схемы передай владельцу MegaMemory.
- Общий порядок хранится здесь; SKILL-документы содержат только указатели и особенности CLI. Bench `--baseline te` сравнивает альтернативный stdout, `lang` не выбирает скилл, `root` refs не меняет cwd runner. Отдельного runtime joint-переключателя нет.

## Выбор источника

- Где определён символ, функция или переменная; кто использует файл; что он использует; как связаны два файла — `graph` (op: `symbol` / `deps` / `rdeps` / `path`).
- Детали реализации — чтение файла.

## Навигация и чтение

- Перед правкой общего файла (сервис, модель, общий модуль, общий хелпер) вызови `graph` (op: `rdeps`) — узнай, что заденет правка.
- `search` — для мест использования текста.
- Файл меньше 300 строк читай напрямую. Файл от 300 строк — сначала `outline`, затем Read(offset, limit) нужного диапазона.

## Правки

- Файл длиннее 50 строк при правке менее 30% — только точечная замена штатным инструментом. Перезаписывать файл целиком запрещено.
- Перед правкой прочитай актуальную версию нужного фрагмента: заменяемый текст должен совпадать с текущим состоянием файла.
- Сущности проекта создавай инструментами скилла (`generate` и аналоги), заготовки руками не пиши. Состав сущностей — в правилах стека.

## Запреты

- Встроенный поиск агента (search_files / grep / ripgrep) не используй никогда: в проектах есть строки длиннее 64 КБ, на которых он обрывается. Весь поиск — только search скилла.
- Не читай файл от 300 строк целиком: сначала outline, затем Read(offset, limit).
- Команды скилла вызывай только одной строкой через argv: `node "<путь>\<скрипт>.js" ключ=значение…` (ts / php / java / kt) или `python "<путь>\scripts\te.py" <команда> …` (py); параметры через пайп/stdin не передавай; не используй `|`, `;`, `&`, `$()`, backtick, `>` — они запрещены правами среды.
- Команда скрипта упала — почини (путь до скрипта, кавычки, значения аргументов) и повтори. Подменять скрипт встроенным поиском или чтением целиком запрещено. Не выходит — спроси меня.
- Не запускай компиляцию, линтер, тесты, полный билд и dev-сервер — об ошибках я сообщу сам.
- Не читай файлы кэша графа (`graph-deps.json`, `.graph-deps-cache.json` и аналоги): только ответы операций `graph`.

# Разработка этого репозитория

- Меняешь файлы скилла — подними `VERSION` (`node skills.js bump <name> <patch|minor|major>`) и прогони `node skills.js verify`. Хеши не пересчитывай руками: только `bump` / `manifest` / `verify`.
- patch — правки без изменения вызовов; minor — новая команда или флаг; major — изменился синтаксис существующих команд.
