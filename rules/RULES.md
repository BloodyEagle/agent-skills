## Выбор источника

- Где определён символ, функция или переменная; кто использует файл; что он использует; как связаны два файла — `graph` (op: `symbol` / `deps` / `rdeps` / `path`).
- Детали реализации — чтение файла.

## Навигация и чтение

- Перед правкой общего файла (сервис, модель, общий модуль, общий хелпер) вызови `graph` (op: `rdeps`) — узнай, что заденет правка.
- `search` — для мест использования текста.
- Файл меньше 300 строк читай напрямую. Файл от 300 строк — сначала `outline`, затем Read(offset, limit) нужного диапазона.

## Правки

- Файл длиннее 50 строк при правке менее 30% — только точечная замена штатным инструментом. Перезаписывать файл целиком запрещено.
- Перед правкой прочитай актуальную версию нужного фрагмента: заменяемый текст должен совпадать с текущим состоянием файла.
- Сущности проекта создавай инструментами скилла (`generate` и аналоги), заготовки руками не пиши. Состав сущностей — в правилах стека.

## Запреты

- Встроенный поиск агента (search_files / grep / ripgrep) не используй никогда: в проектах есть строки длиннее 64 КБ, на которых он обрывается. Весь поиск — только search скилла.
- Не читай файл от 300 строк целиком: сначала outline, затем Read(offset, limit).
- Команды скилла вызывай только одной строкой через argv: `node "<путь>\<скрипт>.js" ключ=значение…` (ts / php / java / kt) или `python "<путь>\scripts\te.py" <команда> …` (py); параметры через пайп/stdin не передавай; не используй `|`, `;`, `&`, `$()`, backtick, `>` — они запрещены правами среды.
- Команда скрипта упала — почини (путь до скрипта, кавычки, значения аргументов) и повтори. Подменять скрипт встроенным поиском или чтением целиком запрещено. Не выходит — спроси меня.
- Не запускай компиляцию, линтер, тесты, полный билд и dev-сервер — об ошибках я сообщу сам.
- Не читай файлы кэша графа (`graph-deps.json`, `.graph-deps-cache.json` и аналоги): только ответы операций `graph`.
