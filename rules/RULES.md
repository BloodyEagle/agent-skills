# Порядок работы и экономия токенов

Скилл token-economy даёт четыре действия: `search`, `outline`, `graph`, `generate`. Чтение и правки файлов выполняй штатными инструментами. Память — через Hindsight (правила в hindsight.md).

## Выбор источника

- Где определён символ, селектор, пайп, переменная или миксин; кто использует файл; что он использует; как связаны два файла — `graph` (op: `symbol` / `selector` / `deps` / `rdeps` / `path`).
- Зачем нужен модуль, как в проекте принято, какие были решения — `recall` из Hindsight.
- Детали реализации — чтение файла.

## Начало задачи

- Для задач, затрагивающих код проекта, первым действием сделай один `recall` из Hindsight: запрос по сути задачи, ограниченный объём результата. Не повторяй `recall` перед каждым вопросом. Для тривиальных правок (опечатка, одна строка в уже известном файле) `recall` пропусти.
- Результат `recall` — подсказка, а не факт. Если он расходится с кодом, верь коду.

## Навигация и чтение

- Перед правкой общего файла (сервис, модель, пайп, общий миксин или переменная стилей) вызови `graph` (op: `rdeps`) — узнай, что заденет правка.
- Вопрос «используется ли компонент / директива / пайп» — `graph` (op: `selector`, затем при необходимости `rdeps`).
- `search` — для мест использования текста. Для html и стилей передавай `ext` (`.html`, `.scss`, `.less`, `.css`).
- Файл меньше 300 строк читай напрямую. Файл от 300 строк — сначала `outline`, затем Read(offset, limit) нужного диапазона.

## Правки

- Файл длиннее 50 строк при правке менее 30% — только точечная замена штатным инструментом. Перезаписывать файл целиком запрещено.
- Перед правкой прочитай актуальную версию нужного фрагмента: заменяемый текст должен совпадать с текущим состоянием файла.
- Сущности Angular (компоненты, сервисы, пайпы, модули, директивы, гварды) создавай только через `generate`, заготовки руками не пиши.

## Запреты

- Не запускай компиляцию, линтер, тесты, полный билд и `ng serve` — об ошибках я сообщу сам.
- Не читай файлы `graph-deps.json` и `.graph-deps-cache.json`: только ответы операций `graph`.
