# Правила памяти Hindsight

Файл проектный: положи его в репозиторий проекта (например, `.kilocode/rules/`), общие правила остаются в rules.md.

## Банк

- bank_id: `my-project` (заменить на имя проекта).
- Не создавай новые банки без разрешения пользователя.

## Что хранить и что нет

Структуру проекта в память не записывай: определения символов, зависимости, точки входа и «кто кого вызывает» всегда актуально отдаёт `graph` скилла token-economy. В память идёт то, что из кода быстро не получить:

- назначение модуля и его место в предметной области;
- соглашения проекта (именование, структура папок, обработка ошибок, работа с API);
- принятые решения и их причины;
- неочевидные ограничения и подводные камни;
- предметные термины;
- исправления пользователя.

Не сохраняй:

- то, что выводится из кода или `graph`: зависимости, пути, номера строк;
- временное состояние текущей задачи;
- секреты: токены, пароли, ключи, адреса внутренних стендов, персональные данные.

## Формат записи (retain)

- Одна сущность на вызов. Не упаковывай несколько модулей в одну запись: теги распространяются на все извлечённые факты.
- Всегда задавай `document_id`: повторный `retain` с тем же `document_id` обновляет запись, а не создаёт дубль. Форматы:
  - `component:<ИмяКласса>` — модуль, сервис, компонент, пайп и т.п.;
  - `convention:<тема>` — соглашение;
  - `decision:<тема>` — решение и причина;
  - `glossary:<термин>` — термин предметной области;
  - `overview:<тема>` — общие сведения о проекте.
- Содержимое — на русском, кратко (2–5 предложений): что делает и зачем, неочевидное, решения и причины. Указывай имя класса или символа, а не путь и номер строки: путь даёт `graph symbol`. В конце — «Актуально на ГГГГ-ММ-ДД».
- Теги — английский, kebab-case: имя компонента (`auth-service` вместо `AuthService`), тип (`service`, `module`, `component`, `api`, `model`, `util`), технология (`angular`, `php`, `nestjs`), домен (`auth`, `billing`, `ui`, `database`). Доменные теги отдельно от тегов компонентов.

Пример:

```
document_id: "component:AuthService"
content: "AuthService отвечает за вход по JWT, обновление токена и сброс пароля. Токен обновляется заранее, за минуту до истечения, чтобы не прерывать запросы. Пароль сбрасывается только через письмо, прямого изменения нет. Актуально на 2026-10-06."
tags: ["auth-service", "service", "nestjs", "auth"]
```

## Начальный анализ (только по команде)

Не запускай анализ автоматически: он тратит много токенов. Если `recall` по тегу `overview` ничего не вернул, сообщи об этом и предложи анализ. Запускай его только по команде пользователя («проанализируй проект»):

1. Дёшево собери исходные данные: `package.json`, `angular.json`, `tsconfig.json`, README, роутинг, дерево папок верхних уровней, `graph` (op: `stats`) — поле `topImported` показывает самые востребованные файлы.
2. Составь план: записи `overview` и список модулей для детального описания (хабы по `topImported`, не больше 30). Покажи план и дождись подтверждения.
3. Запиши обзор: стек и версии, слои, структура папок, соглашения, предметные термины — отдельными записями `overview:<тема>`, `convention:<тема>`, `glossary:<термин>`.
4. По одной записи `component:<ИмяКласса>` на каждый модуль из плана. Для понимания модуля используй `outline` и точечное чтение, не читай файлы целиком без необходимости.
5. В конце предложи создать или обновить «паспорт проекта» — файл `.kilocode/rules/project-passport.md` в репозитории (до 800 токенов: стек и версии, структура папок, главные соглашения, термины). Создавай его только после подтверждения пользователя. Содержимое паспорта в Hindsight не дублируй.
6. Если анализ прервали, продолжи: сделай `recall` по тегам и выясни, что уже записано.

## Накопление по ходу работы

- Если ради задачи пришлось читать модуль, чтобы разобраться, — после задачи сохрани короткую заметку `component:<ИмяКласса>`.
- Если изменилось назначение или поведение компонента — обнови его запись тем же `document_id`.

## Когда делать recall

- Один раз в начале задачи, которая затрагивает код проекта: запрос по сути задачи. Если инструмент позволяет, ограничь объём результата (`max_tokens`, порядка 1000–2000), выбери невысокий бюджет и фильтруй по тегам, когда известен компонент. Результат попадает в контекст, поэтому «бесплатным» он не является.
- Вопросы о структуре («где определено», «кто использует», «от чего зависит») — в `graph`, а не в `recall`.
- Результат — подсказка. Если запись расходится с кодом, верь коду и обнови запись.
- Не говори «ничего не найдено» по смысловым вопросам (зачем, как принято) без `recall`.

## Когда делать retain

- Начальный анализ и накопление по ходу работы (см. выше).
- Пользователь говорит «запомни», «сохрани», «запиши».
- Найдено и согласовано нетривиальное решение — `decision:<тема>`.
- Пользователь поправил тебя: поправка — это договорённость, сохрани её как `convention:<тема>`.
- Принято конфигурационное решение или соглашение.
